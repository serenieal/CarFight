# CarFight Vehicle DA Wizard 화면 설계 초안 v0.1.1

- 작성일: 2026-06-23
- 대상 프로젝트: `UE/CarFight_Re`
- 대상 에디터 툴 후보: `EUW_VDAWizard`
- 대상 작업: 새 차량 `CFVehicleData` DA 입력 보조 화면 설계
- 문서 상태: Draft
- 상위 계획서: `Document/Plan/DataPlan/CF_DAFillToolPlan.md`
- 실무 체크리스트: `Document/Plan/DataPlan/CF_DAFillChecklist.md`

## 1. 문서 목적

이 문서는 `EUW_VDAWizard`를 만들기 전 화면 구조와 사용자 흐름을 고정하기 위한 설계 초안이다.

목표는 예쁜 UI를 먼저 정하는 것이 아니다. 목표는 아래 4가지를 먼저 고정하는 것이다.

1. 사용자가 어떤 순서로 새 차량 DA를 채울지 정한다.
2. 어떤 단계에서 오류, 경고, 정보를 보여줄지 정한다.
3. 어떤 버튼이 실제 데이터를 바꾸고, 어떤 버튼은 검사만 하는지 구분한다.
4. 나중에 C++ 검증 헬퍼를 붙이더라도 화면 구조가 크게 바뀌지 않게 한다.

---

## 2. 기본 방향

`EUW_VDAWizard`는 에디터 유틸리티 위젯(Editor Utility Widget)으로 시작한다.

기본 방향:

- 새 차량 DA를 자동 튜닝하지 않는다.
- 기준 DA와 대상 DA를 비교한다.
- 필수 누락값을 먼저 보여준다.
- 레이아웃 캡처 전 준비 상태를 보여준다.
- Movement 값은 그룹별로 보여준다.
- 사용자가 바꾼 값과 테스트 결과를 남길 수 있게 한다.

툴의 1차 목적은 **좋은 값을 찾아주는 것**이 아니라 **실수 없이 채우게 하는 것**이다.

## 3. 첫 화면 구성

첫 화면은 랜딩 페이지가 아니라 바로 작업 화면이다.

권장 화면 구조:

```text
┌────────────────────────────────────────────────────────────┐
│ 상단 작업 바                                                │
├───────────────┬──────────────────────────────┬─────────────┤
│ 단계 목록      │ 현재 단계 입력/검사 영역       │ 결과/도움말  │
│               │                              │             │
│ 1 필수 참조    │ 기준 DA / 대상 DA             │ 오류 목록     │
│ 2 소켓         │ 필드 그룹                     │ 경고 목록     │
│ 3 레이아웃     │ 비교 테이블                    │ 도움말        │
│ 4 Movement    │ 실행 버튼                      │ 다음 작업     │
│ 5 DriveState  │                              │             │
│ 6 PIE 검증     │                              │             │
└───────────────┴──────────────────────────────┴─────────────┘
```

화면은 크게 4영역으로 나눈다.

1. 상단 작업 바
2. 왼쪽 단계 목록
3. 가운데 입력/검사 영역
4. 오른쪽 결과/도움말 영역

## 4. 상단 작업 바

상단 작업 바는 현재 작업 대상을 고르는 영역이다.

필수 요소:

- 기준 DA 선택
- 대상 DA 선택
- 새 DA 생성
- 전체 검사 실행
- 결과 새로고침

### 4.1 기준 DA 선택

표시명:
- `기준 DA (Source DA)`

기본값:
- `/Game/CarFight/Vehicles/Data/Cars/DA_TestSedan`

동작:
- 사용자가 비교 기준으로 삼을 `CFVehicleData` 자산을 선택한다.
- 기본 추천은 `DA_TestSedan`이지만 하드코딩하지 않는다.

검증:
- [ ] 선택된 자산이 `CFVehicleData`인지 확인한다.
- [ ] 비어 있으면 비교 기능을 비활성화한다.

### 4.2 대상 DA 선택

표시명:
- `대상 DA (Target DA)`

동작:
- 사용자가 입력하거나 검사할 새 차량 DA를 선택한다.

검증:
- [ ] 선택된 자산이 `CFVehicleData`인지 확인한다.
- [ ] 기준 DA와 대상 DA가 같은 경우 경고한다.

### 4.3 새 DA 생성 버튼

표시명:
- `새 차량 DA 생성 (Create Vehicle DA)`

v0.2.0 동작:
- 직접 자산 생성을 자동화하지 않아도 된다.
- 대신 생성 절차 안내와 이름 규칙을 보여준다.

v0.3.0 이후 후보 동작:
- 기준 DA를 복제해 새 DA를 만들 수 있게 한다.

주의:
- 기준 DA를 직접 수정하는 동작은 제공하지 않는다.

### 4.4 전체 검사 실행 버튼

표시명:
- `전체 검사 (Validate All)`

동작:
- 필수 참조, 소켓, 레이아웃, Movement 범위, WheelVisual, DriveState를 한 번에 검사한다.

결과:
- 오류
- 경고
- 정보
- 다음 권장 작업

## 5. 왼쪽 단계 목록

왼쪽 단계 목록은 작업 순서를 고정한다.

단계:

1. 필수 참조
2. 차체 소켓
3. 레이아웃 캡처
4. 기준값 비교
5. Movement 튜닝
6. DriveState 검증
7. PIE 검증
8. 테스트 기록

각 단계는 상태 배지를 가진다.

상태:

- `미확인`
- `정상`
- `경고`
- `오류`
- `보류`

상태 의미:

| 상태 | 의미 | 다음 행동 |
|---|---|---|
| `미확인` | 아직 검사하지 않음 | 단계 열기 또는 전체 검사 |
| `정상` | 필수 조건 통과 | 다음 단계 진행 |
| `경고` | 진행 가능하지만 확인 필요 | 변경 의도 기록 |
| `오류` | 진행하면 실패 가능성 높음 | 먼저 수정 |
| `보류` | 현재 툴 범위 밖 | 수동 확인 또는 다음 버전 |

## 6. 가운데 입력/검사 영역

가운데 영역은 선택된 단계의 실제 내용을 보여준다.

### 6.1 필수 참조 단계

표시 필드:

- `ChassisMesh`
- `WheelMeshFL`
- `WheelMeshFR`
- `WheelMeshRL`
- `WheelMeshRR`
- `FrontWheelClass`
- `RearWheelClass`

표시 방식:

| 필드 | 현재 값 | 상태 | 설명 |
|---|---|---|---|
| `ChassisMesh` | 대상 DA 값 | 오류/정상 | 차체 시각 자산 |
| `WheelMeshFL` | 대상 DA 값 | 오류/정상 | 앞왼쪽 휠 시각 자산 |
| `FrontWheelClass` | 대상 DA 값 | 오류/정상 | 전륜 물리 Wheel Class |

동작:
- [ ] 값이 비어 있으면 오류로 표시한다.
- [ ] FR/RL/RR 휠 메쉬가 비어 있으면 경고로 표시한다.
- [ ] 필드 클릭 시 에디터 세부 정보(`Details`)에서 수정해야 한다고 안내한다.

v0.2.0에서는 툴 안에서 직접 값을 수정하지 않아도 된다.

### 6.2 차체 소켓 단계

표시 필드:

- `BodyWheelSocketFL`
- `BodyWheelSocketFR`
- `BodyWheelSocketRL`
- `BodyWheelSocketRR`

필수 소켓:

- `Wheel_Anchor_FL`
- `Wheel_Anchor_FR`
- `Wheel_Anchor_RL`
- `Wheel_Anchor_RR`

동작:
- [ ] `ChassisMesh`가 없으면 소켓 검사를 비활성화한다.
- [ ] 소켓이 없으면 오류로 표시한다.
- [ ] 소켓 이름이 표준이 아니면 정보로 표시한다.

안내 문구:
- 차체 Static Mesh를 열고 소켓 매니저(`Socket Manager`)에서 소켓 위치를 확인한다.

### 6.3 레이아웃 캡처 단계

표시 필드:

- `bUseLayoutOverrides`
- `WheelAnchorFL`
- `WheelAnchorFR`
- `WheelAnchorRL`
- `WheelAnchorRR`

버튼:
- `레이아웃 캡처 실행 안내 (Open Capture Guide)`

v0.2.0 동작:
- 기존 DA의 `차체 소켓에서 휠 레이아웃 캡처 (Capture Wheel Layout From Chassis Sockets)` 버튼을 누르도록 안내한다.

v0.3.0 이후 후보 동작:
- 대상 DA의 캡처 함수를 직접 호출하는 버튼을 제공한다.

검증:
- [ ] `bUseLayoutOverrides`가 꺼져 있으면 경고한다.
- [ ] 네 앵커 위치가 모두 0에 가까우면 오류로 표시한다.
- [ ] 앞/뒤 또는 좌/우 위치가 의심되면 경고한다.

### 6.4 기준값 비교 단계

표시 방식:

| 그룹 | 필드 | 기준 DA | 대상 DA | 차이 | 위험도 |
|---|---|---:|---:|---:|---|
| Engine | `EngineMaxTorque` | 750 | 850 | +100 | 중간 |
| Steering | `FrontWheelMaxSteerAngle` | 35 | 45 | +10 | 중간 |

초기 비교 대상:

- 엔진 그룹
- 조향 그룹
- 브레이크 그룹
- 접지 그룹
- 서스펜션 그룹
- 고급 물리 그룹
- DriveState 그룹

동작:
- [ ] 값이 다르면 변경 표시를 한다.
- [ ] 위험도가 높은 필드는 우선적으로 오른쪽 도움말에 표시한다.
- [ ] 값이 같으면 접어둘 수 있게 한다.

### 6.5 Movement 튜닝 단계

탭 또는 세그먼트:

- 엔진
- 조향
- 브레이크
- 접지
- 서스펜션
- 고급 물리

각 그룹 표시:

- 필드명
- 현재 값
- 기준 값
- 영향 설명
- 위험도
- 추천 테스트

원칙:
- 한 번에 한 그룹만 열어 작업하게 한다.
- 고급 물리 그룹은 앞 단계가 통과되기 전까지 경고를 표시한다.

### 6.6 DriveState 검증 단계

표시 필드:

- Idle 진입/이탈 임계값
- Reversing 진입/이탈 임계값
- Airborne 임계값
- 상태별 최소 유지 시간
- 입력 임계값
- 반대 스로틀 브레이크 해석 여부

안내:
- DriveState는 물리값이 아니라 상태 판정값이다.
- 차량이 움직이지 않는 문제를 DriveState 값으로 해결하지 않는다.

검증:
- [ ] Idle 진입값이 이탈값보다 높거나 같은지 확인한다.
- [ ] Reversing 진입/이탈 임계값이 의도와 맞는지 확인한다.
- [ ] Airborne 임계값이 0에 너무 가깝지 않은지 확인한다.

### 6.7 PIE 검증 단계

체크 항목:

- 스폰 안정성
- 전진
- 조향
- 브레이크
- 후진
- 휠 시각 위치
- DriveState 안정성

동작:
- [ ] 각 항목을 수동 체크할 수 있다.
- [ ] 실패 항목에 문제 메모를 남길 수 있다.

v0.2.0에서는 PIE를 자동 실행하지 않는다.

### 6.8 테스트 기록 단계

입력 항목:

- 테스트 일시
- 대상 DA
- 기준 DA
- 변경 그룹
- 변경 필드
- 변경 전 값
- 변경 후 값
- 테스트 맵
- PIE 결과
- 문제 현상
- 원인 후보
- 다음 작업

v0.2.0 동작:
- 복사 가능한 텍스트 양식으로 제공한다.

v0.4.0 이후 후보 동작:
- 별도 텍스트 자산 또는 로그 파일로 저장한다.

## 7. 오른쪽 결과/도움말 영역

오른쪽 영역은 현재 단계에서 사용자가 놓치기 쉬운 정보를 보여준다.

구성:

- 오류 목록
- 경고 목록
- 정보 목록
- 선택 필드 도움말
- 다음 권장 작업

### 7.1 오류 목록

오류는 다음 단계 진행을 막아야 하는 항목이다.

예:
- `ChassisMesh`가 비어 있음
- `FrontWheelClass`가 비어 있음
- `bUseLayoutOverrides`가 켜져 있는데 앵커 값이 전부 0

표시:
- 오류 개수
- 오류 필드명
- 해결 방법

### 7.2 경고 목록

경고는 진행은 가능하지만 확인이 필요한 항목이다.

예:
- `CenterOfMassOverride`가 켜져 있음
- 기준 DA보다 조향각이 크게 큼
- DriveState 값이 기준 DA와 크게 다름

표시:
- 경고 개수
- 의도 확인 체크
- 테스트 권장 항목

### 7.3 선택 필드 도움말

필드 선택 시 아래 정보를 보여준다.

- 표시 이름
- 내부 필드명
- 단위
- 영향
- 위험도
- 먼저 해볼 테스트
- 되돌릴 때 볼 기준값

예:

```text
필드: EngineMaxTorque
영향: 가속력과 휠스핀 가능성을 키운다.
위험도: 중간
테스트: 직선 가속 5초, 출발 시 좌우 흔들림 확인
```

## 8. 버튼 책임 분리

버튼은 검사 버튼과 변경 버튼을 명확히 구분한다.

### 8.1 검사 버튼

데이터를 바꾸지 않는다.

후보:
- `전체 검사 (Validate All)`
- `필수 참조 검사 (Validate References)`
- `소켓 검사 (Validate Sockets)`
- `레이아웃 검사 (Validate Layout)`
- `기준값 비교 (Compare With Source)`

### 8.2 변경 버튼

데이터를 실제로 바꿀 수 있다.

후보:
- `새 차량 DA 생성 (Create Vehicle DA)`
- `기준값 복사 (Copy From Source)`
- `레이아웃 캡처 실행 (Capture Layout)`
- `테스트 기록 저장 (Save Test Note)`

원칙:
- 변경 버튼은 실행 전 확인 문구를 띄운다.
- 기준 DA를 바꾸는 변경 버튼은 만들지 않는다.
- v0.2.0에서는 변경 버튼보다 검사 버튼을 우선 구현한다.

## 9. 데이터 상태 모델

화면 내부에서는 각 검사 결과를 아래 상태로 본다.

```text
Unchecked
Pass
Info
Warning
Error
Blocked
```

표시 이름:

| 내부 상태 | 표시 이름 | 의미 |
|---|---|---|
| `Unchecked` | 미확인 | 아직 검사하지 않음 |
| `Pass` | 정상 | 다음 단계 진행 가능 |
| `Info` | 정보 | 확인용 차이 또는 안내 |
| `Warning` | 경고 | 진행 가능하지만 의도 확인 필요 |
| `Error` | 오류 | 수정 전 진행 금지 |
| `Blocked` | 보류 | 툴 범위 밖 또는 선행 조건 부족 |

## 11. 블루프린트 변수/함수 툴팁 제안

`EUW_VDAWizard`를 블루프린트로 만들 때 사용할 수 있는 변수와 함수 툴팁 초안이다.

### 11.1 변수 후보

| 변수명 | 표시 이름 | 툴팁 |
|---|---|---|
| `SourceVehicleData` | 기준 차량 DA | 비교 기준으로 사용할 차량 데이터 자산입니다. 기본 추천은 DA_TestSedan입니다. |
| `TargetVehicleData` | 대상 차량 DA | 현재 입력하거나 검사할 새 차량 데이터 자산입니다. |
| `ValidationResultList` | 검사 결과 목록 | 전체 검사에서 발견한 오류, 경고, 정보 항목입니다. |
| `SelectedStepName` | 선택 단계 이름 | 왼쪽 단계 목록에서 현재 선택된 작업 단계 이름입니다. |
| `SelectedFieldName` | 선택 필드 이름 | 도움말 영역에 설명을 표시할 현재 선택 필드 이름입니다. |

### 11.2 함수 후보

| 함수명 | 표시 이름 | 툴팁 |
|---|---|---|
| `RefreshWizardView` | Wizard 화면 갱신 | 현재 기준 DA와 대상 DA를 기준으로 화면 표시와 검사 요약을 다시 그립니다. |
| `ValidateAllSteps` | 전체 단계 검사 | 필수 참조, 소켓, 레이아웃, 주요 수치 차이를 한 번에 검사합니다. |
| `ValidateRequiredRefs` | 필수 참조 검사 | 대상 DA의 차체, 휠 메쉬, Wheel Class 누락 여부를 검사합니다. |
| `ValidateWheelSockets` | 휠 소켓 검사 | 대상 DA의 차체 메쉬에 필요한 Wheel_Anchor 소켓이 있는지 검사합니다. |
| `CompareWithSourceDA` | 기준 DA와 비교 | 기준 DA와 대상 DA의 주요 차량 수치를 비교해 차이와 위험도를 표시합니다. |

주의:
- 위 이름은 블루프린트 내부 후보명이다.
- 에디터 표시 문구는 한국어(English) 병기 방식을 유지한다.
