## 0. 문서 목적

이 문서는 Tripo의 이미지 입력 기반 3D 생성 기능을 사용할 때, 어떤 종류의 오브젝트든 공통 적용할 수 있는 입력 이미지 제작 기준을 정리한 문서다.

이 문서는 특정 프로젝트의 특정 오브젝트만을 다루지 않는다.

즉, 아래 대상 모두에 적용 가능해야 한다.

1. 차량 부품
2. 터렛
3. 무기
4. 소품
5. 공용 오브젝트
6. 구조물 일부
7. 공구류
8. 장치류
9. 장식성 오브젝트
10. 단순 하드서피스 자산

이 문서의 목적은 다음과 같다.

1. Tripo가 가장 안정적으로 형태를 해석할 수 있는 입력 이미지 조건을 정한다.
2. 컨셉이미지/문서용 이미지와 실제 Tripo 입력용 이미지를 구분한다.
3. 컨셉이미지에는 조립된 완성 오브젝트를 표시할 수 있고, Tripo 입력용 이미지에는 실제 생성할 단일 메시 파츠만 표시한다는 기준을 정한다.
4. 같은 메시 파츠의 Quarter View와 Front / Back / Left / Right를 한 장에 배치하는 쿼터뷰 + 4뷰 단일 이미지 시트 기준을 정한다.
5. 쿼터뷰 + 4뷰 단일 이미지 시트와 4장 분리 멀티뷰 입력의 장단점을 정리한다.
6. 이미지 한 장, 쿼터뷰 + 4뷰 단일 이미지 시트, 또는 멀티뷰 4장 분리 입력 시 지켜야 할 공통 규칙을 정한다.
7. Blender 수동 수정 비전제 상황에서, Tripo 입력 이미지를 더 안전하게 준비하는 방법을 정한다.
8. 오브젝트 전용 문서가 참조할 수 있는 상위 공통 입력 규칙을 제공한다.

## 1. 전제 조건

### 1.1 Tripo 입력 방식 전제

Tripo의 이미지/텍스트 입력 방식은 아래와 같이 가정한다.

1. 쿼터뷰 이미지 1장 입력
2. 멀티뷰 이미지 4장 입력
3. 이미지 일괄 3D 변환
4. 텍스트 입력

한 번 생성할 때는 위 방법 중 한 가지만 사용한다.

텍스트와 이미지를 동시에 넣어 세부 제어하는 방식은 기본 전제로 두지 않는다.

### 1.2 작업 환경 전제

이 문서는 아래 작업 환경을 전제로 한다.

1. 사용자는 Blender 수동 모델링을 하지 않는다.
2. Blender는 메시 로드, 스크립트 실행, Export 정도로만 사용한다.
3. 수동 리토폴로지, 수동 메시 분리, 수동 면 정리는 기본 파이프라인에 포함하지 않는다.
4. 따라서 Tripo 입력 단계에서 최대한 완성도 높은 형태를 확보해야 한다.

## 2. 입력 방식 평가

### 2.1 쿼터뷰 이미지 1장 입력

#### 장점

1. 한 장에서 앞/옆/윗면 느낌을 어느 정도 동시에 전달할 수 있다.
2. 초기 아이디어 탐색에 좋다.
3. 상부 형상 인상을 어느 정도 전달할 수 있다.

#### 단점

1. 반대편 정보가 부족하다.
2. 후면 구조가 불안정하다.
3. 비례 오차가 생기기 쉽다.
4. 정밀한 하드서피스 오브젝트에는 불리하다.

#### 용도

```text
아이디어 탐색
형태 후보 생성
초기 러프 테스트
```

### 2.2 쿼터뷰 + 4뷰 단일 이미지 시트 입력

쿼터뷰 + 4뷰 단일 이미지 시트 입력은 한 장 안에 같은 오브젝트의 Quarter View 1개와 Front / Back / Left / Right를 함께 배치하는 방식이다.

#### 권장 배치

```text
Left Large Area: Quarter View
Right Top Left: Front View
Right Top Right: Back View
Right Bottom Left: Left View
Right Bottom Right: Right View
```

#### 장점

1. 이미지 생성 비용과 토큰 사용량을 줄일 수 있다.
2. 같은 파츠의 입체감과 앞/뒤/좌/우 형태를 한 번에 전달할 수 있다.
3. 파츠별 입력 이미지를 관리하기 쉽다.
4. 여러 파츠를 따로 생성해야 할 때 전체 이미지 수를 크게 줄일 수 있다.

#### 단점

1. Tripo가 쿼터뷰와 4개 뷰를 하나의 시트로 정확히 해석하지 못할 수 있다.
2. 뷰 사이 간격이 좁거나 배치가 불명확하면 하나의 복잡한 오브젝트처럼 오해할 수 있다.
3. 4장 분리 입력보다 각 뷰의 해상도와 세부 정보량이 줄어들 수 있다.

#### 용도

```text
기본 비용 절감 입력 방식
파츠별 3D 생성
반복 제작용 실무 입력 방식
```

### 2.3 멀티뷰 이미지 4장 분리 입력

#### 장점

1. Front / Back / Left / Right 비례를 가장 안정적으로 전달할 수 있다.
2. 폭, 높이, 길이, 두께 등 기본 형상이 잘 고정된다.
3. 하드서피스 구조물에 가장 유리하다.
4. 반복 제작과 재현성이 좋다.

#### 단점

1. Top View와 Bottom View 정보가 직접 들어가지 않는다.
2. 상부와 하부의 세부 정보는 손실될 수 있다.
3. 입력 이미지 품질이 조금만 흔들려도 모순이 생길 수 있다.

#### 용도

```text
정밀도 우선 옵션
쿼터뷰 + 4뷰 단일 이미지 시트 결과가 불안정할 때의 대체 방식
최종 중요 자산 재생성용
```

### 2.4 이미지 일괄 3D 변환

#### 장점

1. 후보를 많이 만들기 좋다.
2. 생산량 위주 탐색에 유리하다.

#### 단점

1. 각 이미지가 독립 메시가 되므로 정밀 제작에 직접 연결하기 어렵다.
2. 결국 단일 이미지 입력의 한계를 그대로 가진다.

#### 용도

```text
대량 후보 탐색
초기 러프 변형 생성
```

### 2.5 텍스트 입력

#### 장점

1. 매우 빠르게 아이디어를 시도할 수 있다.
2. 스타일 탐색에 좋다.

#### 단점

1. 파츠 경계와 구조 제어가 약하다.
2. 기계 구조, 장착면, 접합부, 피벗 위치 정확도가 낮다.
3. 이미지 기반보다 재현성이 떨어질 수 있다.
4. 최대 글자 수 제한 때문에 복잡한 오브젝트 조건을 모두 넣기 어렵다.

#### 용도

```text
아이디어 스케치
초기 컨셉 탐색
```

### 2.6 기본 권장 결론

비용 절감과 반복 제작을 우선할 경우, 기본 권장 방식은 다음이다.

```text
파츠별 쿼터뷰 + 4뷰 단일 이미지 시트 1장 입력
```

정밀도를 최우선으로 하거나 쿼터뷰 + 4뷰 단일 이미지 시트 결과가 불안정할 경우, 다음 방식을 보조 옵션으로 사용한다.

```text
Front / Back / Left / Right 4장 분리 입력
```

아래 조건에서는 다른 방식을 보조적으로 사용할 수 있다.

1. 초반 아이디어 탐색만 할 때
2. 상부 인상을 먼저 보고 싶을 때
3. 매우 단순한 오브젝트일 때
4. 최종용이 아니라 후보용일 때

## 3. 이미지 종류의 구분

### 3.1 컨셉이미지 / 문서 검수용 이미지

컨셉이미지 또는 문서 검수용 이미지는 사람이 구조, 규칙, 간섭, 비례, 완성 상태를 검토하기 위한 이미지다.

이 이미지는 실제 Tripo 입력용 이미지와 다르다.

컨셉이미지에는 아래 내용을 표시할 수 있다.

1. 여러 파츠가 조립된 완성 오브젝트 전체
2. 전체 실루엣
3. 전체 비례
4. 파츠 간 위치 관계
5. 장착 상태
6. 회전 반경 또는 간섭 확인용 Top View
7. 콜아웃, 텍스트, 치수선, 설명 표기, 참고 라벨

예를 들어 터렛 컨셉이미지는 아래처럼 표시할 수 있다.

```text
TurretBaseMesh + TurretYawMesh + TurretPitchMesh
= 조립된 완성 터렛 전체
```

이 경우 컨셉이미지를 파츠별로 분해해서 보여주는 것은 기본값이 아니다.

분해도는 필요할 때만 보조 `Exploded Reference`로 사용한다.

### 3.2 Tripo 입력용 이미지

Tripo 입력용 이미지는 실제로 Tripo에 넣는 이미지다.

이 이미지는 설명용 이미지가 아니라, Tripo가 “하나의 생성 대상”을 안정적으로 읽기 위한 입력용 이미지다.

따라서 Tripo 입력용 이미지는 아래 원칙을 따른다.

1. 실제 생성할 메시 파츠 하나만 보여야 한다.
2. 여러 파츠가 조립된 완성 오브젝트를 넣지 않는다.
3. 텍스트를 넣지 않는다.
4. 치수선을 넣지 않는다.
5. 콜아웃을 넣지 않는다.
6. 서로 다른 오브젝트나 서로 다른 파츠를 한 장에 섞지 않는다.
7. 같은 메시 파츠의 Quarter View와 Front / Back / Left / Right를 한 장에 배치한 쿼터뷰 + 4뷰 단일 이미지 시트는 허용한다.
8. 배경은 단순해야 한다.
9. 조명과 스케일이 일관되어야 한다.

예를 들어 최종 게임 오브젝트가 Base/Yaw/Pitch 3개 메시로 구성된다면, Tripo 입력용 이미지는 아래처럼 나눈다.

```text
Base 쿼터뷰 + 4뷰 단일 이미지 시트
YawMesh 쿼터뷰 + 4뷰 단일 이미지 시트
PitchMesh 쿼터뷰 + 4뷰 단일 이미지 시트
```

### 3.3 핵심 구분 원칙

```text
컨셉이미지:
사람이 완성 상태를 검토하기 위한 이미지.
조립된 전체 오브젝트를 보여줄 수 있다.

Tripo 입력용 이미지:
AI가 실제 메시 하나를 만들기 위한 이미지.
생성 대상 파츠 하나만 보여준다.
```

## 4. Tripo 입력용 이미지 공통 규칙

### 4.1 가장 중요한 원칙

Tripo 입력용 이미지는 “설명서”가 아니라, “깨끗한 단일 오브젝트 이미지”처럼 보여야 한다.

### 4.2 공통 규칙

Tripo 입력용 이미지는 아래 조건을 만족해야 한다.

1. 한 장에는 실제 생성할 메시 파츠 하나만 들어간다.
2. 같은 메시 파츠의 Quarter View와 Front / Back / Left / Right를 한 장에 배치한 쿼터뷰 + 4뷰 단일 이미지 시트는 허용한다.
3. 여러 파츠가 조립된 완성 오브젝트를 넣지 않는다.
4. 이미지 안에 다른 오브젝트를 같이 넣지 않는다.
5. 최종 오브젝트가 여러 메시 파츠로 구성된다면, 파츠별로 입력 이미지 세트를 분리한다.
6. 배경은 단색 또는 매우 단순한 배경으로 한다.
7. 텍스트, 치수선, 주석, 화살표를 넣지 않는다.
8. 그림자는 완전히 없어야 하며, 접지 그림자/그라데이션 그림자/강한 음영을 모두 넣지 않는다.
9. 조명은 형태를 읽을 수 있을 정도로만 균일하게 사용하고, 그림자가 생기지 않는 shadowless lighting을 기본으로 한다.
10. 반사도 과하지 않아야 하며, 반사광이 외곽선이나 접합부를 흐리게 만들면 안 된다.
11. 오브젝트는 프레임 안에 충분히 크게 잡는다.
12. 오브젝트가 잘리지 않게 한다.
13. 중심이 너무 치우치지 않게 한다.
14. 카메라/시점 규칙을 일관되게 유지한다.
15. 쿼터뷰 + 4뷰 단일 이미지 시트 안의 다섯 뷰는 모두 같은 스케일과 같은 기준축을 유지한다.
16. 4장 분리 입력을 쓸 경우 네 장 모두 같은 스케일과 같은 기준축을 유지한다.
17. 투명 배경 또는 단색 배경 중 하나로 통일한다.
18. 한 세트 안에서 재질 표현과 선명도를 통일한다.

### 4.3 금지 요소

다음 요소는 Tripo 입력용 이미지에 넣지 않는다.

1. 여러 파츠가 조립된 완성 오브젝트
2. 컨셉이미지용 조립 상태 이미지
3. 콜아웃 텍스트
4. 파츠 이름 표기
5. 치수선
6. 도식 화살표
7. 서로 다른 오브젝트나 서로 다른 파츠를 한 장에 섞은 콜라주 시트
8. 쿼터뷰 + 4뷰 단일 이미지 시트 안에서 뷰 순서가 불명확한 구성
9. 복잡한 배경 사진
10. 여러 개의 오브젝트 동시 배치
11. 다른 물체와의 접촉/겹침
12. 과한 원근 왜곡
13. 강한 모션감
14. 연출용 이펙트
15. 모든 종류의 그림자
16. 접지 그림자
17. 그라데이션 그림자
18. 강한 명암 음영
19. 지나치게 어두운 조명

## 5. 멀티뷰 4장 입력 규칙

### 5.1 권장 뷰 구성

멀티뷰 4장 입력 시 기본 구성은 다음을 권장한다.

```text
Front
Back
Left
Right
```

이 네 장은 반드시 같은 오브젝트의 서로 다른 방향이어야 한다.

### 5.2 일관성 규칙

네 장은 아래 조건을 반드시 맞춰야 한다.

1. 스케일이 같아야 한다.
2. 중심 위치가 비슷해야 한다.
3. 카메라 거리감이 같아야 한다.
4. 조명 조건이 같아야 한다.
5. 배경이 같아야 한다.
6. 렌더/표현 방식이 같아야 한다.
7. 재질 느낌이 같아야 한다.
8. 오브젝트가 같은 높이 기준선에 놓여야 한다.
9. 좌우 방향이 서로 모순되지 않아야 한다.
10. Front와 Back, Left와 Right의 폭/높이 비례가 서로 맞아야 한다.

### 5.3 정사영에 가까운 표현 권장

가능하면 정사영에 가까운 뷰를 사용한다.

이유는 다음과 같다.

1. 폭, 높이, 두께를 안정적으로 읽히게 한다.
2. 원근감으로 인한 왜곡을 줄인다.
3. 하드서피스 오브젝트에 특히 유리하다.

### 5.4 상부/하부 정보 부족에 대한 대응

멀티뷰 4장 입력은 Top / Bottom 정보를 직접 넣지 못한다.

따라서 입력 대상 오브젝트는 아래 기준으로 설계하는 것이 좋다.

1. 상부에서만 읽히는 복잡한 디테일을 피한다.
2. 하부에서만 읽히는 복잡한 브래킷을 피한다.
3. 상부 형상은 Front / Back / Left / Right에서도 어느 정도 드러나게 만든다.
4. 하부는 단순 접합면이나 단순 평면 구조로 유지한다.
5. 상하 정보가 없어도 큰 실루엣이 유지되도록 만든다.
6. Top View는 Tripo 입력용이 아니라 문서/검수용 이미지로 따로 유지한다.

## 6. 쿼터뷰 1장 입력 규칙

### 6.1 적합한 사용 목적

쿼터뷰 1장 입력은 아래 용도에 적합하다.

1. 초기 아이디어 확인
2. 형태 분위기 탐색
3. 단순 오브젝트의 빠른 테스트
4. 멀티뷰 제작 전 후보 압축

### 6.2 주의사항

1. 최종 하드서피스 자산용 정밀 제작 기준으로는 불안정할 수 있다.
2. 반대편이나 후면 구조가 틀어질 수 있다.
3. 하부 접합부와 장착면이 틀어질 수 있다.
4. 한 장에 보이지 않는 구조는 Tripo가 추정해서 만들 수 있다.

### 6.3 권장 상황

아래 조건이면 쿼터뷰 1장 입력을 고려할 수 있다.

1. 오브젝트가 대칭적일 때
2. 형태가 매우 단순할 때
3. 완성도보다 탐색이 중요할 때
4. 상부 인상 확인이 중요할 때

## 8. Blender 사용 전제

### 8.1 기본 전제

이 문서는 사용자가 Blender를 수동 모델링 도구로 쓰지 않는다는 전제를 따른다.

### 8.2 허용 사용 범위

Blender는 다음 용도로만 사용한다.

1. Tripo 결과 메시 로드
2. 제공된 스크립트 실행
3. 결과 메시 Export

### 8.3 비전제 작업

다음 작업은 기본 전제로 두지 않는다.

1. 수동 메시 분리
2. 수동 버텍스 수정
3. 수동 면 삭제
4. 수동 리토폴로지
5. 수동 노멀 정리
6. 수동 장착면 보정
7. 수동 디테일 추가

### 8.4 Tripo 입력 단계의 중요성

Blender 수동 수정이 어렵기 때문에, Tripo 입력 이미지는 처음부터 아래 목표를 가져야 한다.

1. 큰 형태가 정확해야 한다.
2. 하부 구조가 단순해야 한다.
3. 상부 구조가 단순해야 한다.
4. 접합부가 명확해야 한다.
5. 불필요한 얇은 디테일이 없어야 한다.
6. 스크립트 기반 정렬/원점/스케일 정리가 가능해야 한다.

## 9. 입력 이미지 제작 체크리스트

8. 최종 오브젝트가 여러 메시 파츠라면 파츠별 입력 이미지 세트로 분리했는가?

10. 그림자가 완전히 없는가?
11. 접지 그림자, 그라데이션 그림자, 강한 음영이 모두 없는가?

13. 텍스트와 치수선이 없는가?
14. 콜아웃과 파츠 이름 표기가 없는가?
15. 쿼터뷰 + 4뷰 단일 이미지 시트라면 한 장 안에 Quarter / Front / Back / Left / Right가 모두 들어가 있는가?

18. 4장 분리 입력이라면 네 장의 스케일, 중심, 조명, 배경이 같은가?
19. 4장 분리 입력이라면 Front / Back / Left / Right 방향이 명확한가?
20. 상부/하부에만 의존하는 복잡한 디테일을 넣지 않았는가?
21. 오브젝트의 큰 실루엣이 명확한가?
22. 얇은 케이블/기어/안테나가 과하지 않은가?
23. Blender 수동 수정 없이도 쓸 수 있을 정도로 단순한가?
24. 스크립트로 원점/스케일/방향 정리를 할 수 있는 구조인가?

## 10. 권장 제작 파이프라인

범용 오브젝트 제작 시, 아래 흐름을 권장한다.

### 10.1 탐색 단계

```text
텍스트 입력 또는 쿼터뷰 1장 입력
→ 러프 후보 생성
→ 방향 확인
```

### 10.2 최종 제작 단계

```text
컨셉이미지/문서 검수용 이미지 준비

→ 실제 생성할 메시 파츠 목록 확정
→ 파츠별 쿼터뷰 + 4뷰 단일 이미지 시트 준비
→ 파츠별 쿼터뷰 + 4뷰 단일 이미지 시트 입력
→ Tripo 3D 생성
→ Blender에서 스크립트 실행
→ Export
```

### 10.3 컨셉이미지와 Tripo 입력 이미지 활용

```text
컨셉이미지:
- 조립된 완성 오브젝트 전체 검수
- 전체 실루엣, 비례, 장착 상태, 간섭 확인
- 필요 시 Top View와 콜아웃 포함 가능

Tripo 입력용 이미지:
- 실제 생성할 메시 파츠 단독 쿼터뷰 + 4뷰 이미지 시트
- Quarter View는 왼쪽 큰 영역에 배치
- Front / Back / Left / Right는 오른쪽 2x2 그리드로 배치
- 필요 시 정밀도 우선 옵션으로 4장 분리 입력 사용
- 텍스트, 치수선, 콜아웃, 조립 상태 이미지 금지
```

## 13. Migration

이 문서는 특정 오브젝트 전용 문서를 대체하지 않는다.

이 문서는 다음 역할을 가진다.

1. Tripo 입력 이미지 제작의 상위 공통 규칙
2. 오브젝트별 문서가 참조해야 하는 입력 이미지 기준
3. 수동 Blender 비전제 환경에서의 안전한 운영 원칙

예를 들어 아래처럼 사용한다.

```text
터렛 원화 규칙:
16_WeaponArtRules.md

Tripo 입력 이미지 공통 규칙:
17_TripoInputImageRules.md
```

즉, 오브젝트 전용 문서는 각 오브젝트의 구조/역할/금지 요소를 다루고, 이 문서는 “Tripo에 넣기 위한 이미지 제작 방식” 자체를 다루는 문서다.

### v0.5 적용 기준

기존 v0.4의 입력 이미지 기준에 그림자 금지 조건을 추가한다.

앞으로 Tripo 입력용 이미지는 다음 조건을 반드시 만족해야 한다.

```text
no shadows
no cast shadow
no contact shadow
no ground shadow
no gradient shadow
shadowless lighting
flat clean background
```

그림자가 있으면 Tripo가 그림자를 하부 형상, 접지면, 돌출 파츠, 구멍, 재질 변화로 오해할 수 있으므로 기본 입력 이미지에서는 모든 그림자를 금지한다.

### v0.4 적용 기준

기존 v0.3의 `4뷰 단일 이미지 시트` 기본 기준은 `쿼터뷰 + 4뷰 단일 이미지 시트`로 확장한다.

앞으로 기본 비용 절감 입력 방식은 다음과 같다.

```text
Left Large Area: Quarter View
Right Top Left: Front View
Right Top Right: Back View
Right Bottom Left: Left View
Right Bottom Right: Right View
```

서로 다른 오브젝트나 서로 다른 파츠를 한 장에 섞는 것은 계속 금지한다.

4장 분리 입력은 폐기하지 않고 정밀도 우선 옵션으로 유지한다.

### v0.3 적용 기준

기존 v0.2의 `Tripo 입력용 이미지는 여러 뷰를 한 장에 합치지 않는다` 해석은 폐기한다.

앞으로 Tripo 입력용 이미지에서 금지하는 것은 서로 다른 오브젝트나 서로 다른 파츠를 한 장에 섞는 것이다.

같은 메시 파츠의 Front / Back / Left / Right 4뷰를 2x2 그리드로 한 장에 배치하는 것은 허용하며, 비용 절감 기본 방식으로 사용한다.

4장 분리 입력은 폐기하지 않고 정밀도 우선 옵션으로 유지한다.

### v0.2 적용 기준

기존 문서에서 `문서/검수용 이미지`라고 부르던 표현은 문맥상 `컨셉이미지/문서 검수용 이미지`로 해석한다.

오브젝트 전용 문서는 앞으로 아래 두 항목을 반드시 분리해 적는다.

1. 컨셉이미지에 표시할 대상
2. Tripo 입력용 이미지에 표시할 대상

다중 파츠 오브젝트의 기본 해석은 다음과 같다.

```text
컨셉이미지:
- 조립된 완성 오브젝트 전체
- 전체 실루엣, 비례, 장착 상태, 간섭 검수

Tripo 입력용 이미지:
- 실제 생성할 메시 파츠 단독 이미지 세트
- 여러 파츠가 조립된 완성 오브젝트 금지
```

분해도는 기본 컨셉이미지가 아니다.

분해도가 필요하면 보조 `Exploded Reference`로만 사용한다.
