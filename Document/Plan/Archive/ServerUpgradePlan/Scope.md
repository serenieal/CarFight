# 서버 고도화 작업 범위

- 문서 버전: v0.1.0
- 작성일: 2026-06-01
- 대상 프로젝트: CarFight
- 상위 문서: `README.md`
- 상태: Active

---

## 1. 목적

이 문서는 CarFight 서버 고도화 작업에서 지금 할 일과 하지 않을 일을 명확히 고정한다.

현재 목표는 멀티플레이 전체 완성이 아니다.

현재 목표는 다음이다.

```text
현재 클라이언트에 이미 구현된 차량 플레이 기능을 Dedicated Server 환경에서 안정적으로 실행, 소유, 조작, 관찰할 수 있게 만든다.
```

---

## 2. 현재 포함 범위

이번 단계에서 포함하는 작업은 아래와 같다.

```text
- Dedicated Server 실행 기준 유지
- 클라이언트 2개 접속 검증
- 서버 권한 Player Spawn / Vehicle Spawn / Possess 구조 작성
- 각 클라이언트의 자기 차량 소유권 확인
- OwnerOnly 입력 분리 확인
- 차량 이동 복제 확인
- Dedicated Server에서 UI, 카메라, 로컬 사운드 코드가 실행되지 않도록 정리
- 현재 구현된 Aim / Fire 요청 골격의 서버 권한 경계 확인
- TestMap을 2클라 검증 가능한 최소 구조로 정리
- 서버 로그 / 클라이언트 로그 기준 검증 절차 문서화
```

아래 기능은 이번 단계에서 새로 만들지 않는다.

## 4. 예외적으로 허용되는 신규 코드

이번 단계는 새 gameplay 시스템 구현을 제한하지만, 아래 신규 코드는 허용한다.

```text
- Dedicated Server 테스트용 최소 GameMode
- 서버 Spawn/Possess helper 함수
- 서버/클라이언트 역할 분리용 최소 PlayerController, 필요 시
- Dedicated Server 안전성 확보를 위한 guard 함수
- 로그와 검증을 위한 최소 디버그 코드
```

이 코드는 신규 시스템이 아니라 현재 구현 기능을 Dedicated Server에서 검증하기 위한 기반 코드다.

## 6. 단계 완료 기준

이번 서버 고도화 1차 단계는 아래 조건을 만족하면 완료로 본다.

```text
1. Dedicated Server가 TestMap 또는 서버 테스트맵을 로드한다.
2. 클라이언트 2개가 서버에 접속한다.
3. 각 클라이언트가 자기 차량 Pawn을 소유한다.
4. 클라이언트 A 입력은 A 차량에만 적용된다.
5. 클라이언트 B 입력은 B 차량에만 적용된다.
6. 클라이언트 A 화면에서 B 차량 이동이 보인다.
7. 클라이언트 B 화면에서 A 차량 이동이 보인다.
8. Dedicated Server 로그에 UI, 카메라, LocalPlayer, 사운드 관련 오류가 없다.
9. 아직 구현되지 않은 gameplay 시스템을 추가하지 않는다.
```

---

## 7. 범위 이탈 판단 기준

아래 상황이 발생하면 범위 이탈로 본다.

```text
- 차량 소유권 검증 전에 무기 구현을 시작한다.
- 이동 복제 검증 전에 대미지/체력을 만든다.
- Dedicated Server 오류 정리 전에 로비/세션을 만든다.
- TestMap 2클라 검증 전에 서버 배포 자동화를 고민한다.
- 서버 권한 구조가 없는 상태에서 클라이언트 RPC만 늘린다.
```
