## 1. 목적

`Document/Plan/CombatPlan/`은 CarFight의 전략 / 전투 시스템 기획을 누적 관리하는 전용 폴더다.

이 폴더는 단일 문서를 저장하기 위한 임시 위치가 아니라, 전투 시스템의 기준 문서들을 관리하는 계획 문서 허브로 사용한다.

관리 범위는 다음과 같다.

- 전투 정체성
- 승패 요소
- 교전 흐름
- 차량 기동과 거리 / 각도 규칙
- 조준 방식
- 무기 타입
- 탄종 / 탄수 / 중량
- 장갑 방향과 피해 타입
- 락온 / 센서 / 전자전
- 배터리 / 연료 운용
- 무기별 과열
- 하드포인트 / 무기 그룹
- 피팅 시스템
- 전투 UI
- AI 전투 역할
- P0 / P1 전투 프로토타입 범위
- 밸런싱 기준

## 2. 최상위 기획 원칙

CarFight는 EVE Online의 전략 구조와 Elite Dangerous의 직접 전투 감각을 참고하지만, 같은 시스템을 그대로 복제하지 않는다.

CarFight의 전투 정체성은 반드시 자동차 기반으로 재해석한다.

핵심 원칙은 다음과 같다.

1. 전략 구조는 피팅, 거리, 역할, 상성, 작전 준비를 중심으로 둔다.
2. 전투 조작은 직접 조준, 차량 기동, 하드포인트, 무기 그룹 운용을 중심으로 둔다.
3. 차량 자원은 배터리 / 연료 / 탄약 / 중량 / 모듈 상태로 분리한다.
4. 열은 차량 전체 자원이 아니라 무기별 자원으로 둔다.
5. 탄종과 탄수는 피팅의 일부이며, 차량 중량과 직접 연결한다.
6. 자동차성은 접지, 선회, 제동, 충돌, 장갑 방향, 지형 전투에서 드러나야 한다.
7. 고정 무기가 아닌 모든 무기에는 각속도와 조준 안정화 개념을 둔다.
8. 대응 없는 락온 / 전자전 / 상태이상은 금지한다.
9. 현재 `CombatPlan`의 P0 / P1 전투 기준은 싱글플레이 AI 교전으로 둔다.
10. 멀티플레이, 팀전, 서버 / 네트워크 전제는 현재 `CombatPlan` 범위에서 제외한다.

## 4. 문서 작성 규칙

각 문서는 가능하면 다음 상단 메타데이터 형식을 사용한다.

```text
- 문서 버전: v0.1
- 작성일: YYYY-MM-DD
- 최근 갱신일: YYYY-MM-DD
- 문서 상태: Current
- 담당 범위: ...
```

각 문서는 다음 항목을 포함하는 것을 기본으로 한다.

- 목적
- 핵심 정의
- 결정안
- P0 범위
- P1 이후 확장 후보
- 아직 정하지 않은 것
- 다음 작업
- Changelog
- Migration 메모가 필요한 경우 별도 표기

문서 상태는 아래 중 하나를 사용한다.

| 상태 | 의미 |
|---|---|
| Draft | 초안 |
| Current | 현재 기준 |
| Pending | 검토 필요 |
| Locked | 당분간 고정 |
| Replaced | 다른 문서로 대체됨 |
| Archived | 보관됨 |

## 5. 운영 방식

새 기획을 정할 때는 먼저 `00_Index.md`에서 위치를 확인한다.

결정된 내용은 해당 번호 문서에 반영하고, 중요한 결정은 `DecisionLog.md`에도 별도로 기록한다.

세부 수치 밸런스는 초기에 확정하지 않는다. 먼저 전투 정체성, 구조, 역할, 상호작용을 정한 뒤 P0 프로토타입 범위를 확정한다.

문서명 변경이나 실제 파일명 변경이 발생하면 아래 문서를 함께 갱신한다.

- `README.md`
- `00_Index.md`
- `DecisionLog.md`
- 관련 상세 문서의 다음 작업 / 관련 문서 문구
- `Template.md`의 예시 파일명
