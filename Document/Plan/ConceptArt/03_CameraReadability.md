# CarFight Concept Art - Camera Readability

문서 버전: v0.1  
작성일: 2026-07-06  
문서 위치: `Document/Plan/ConceptArt/03_CameraReadability.md`  
상위 기준 문서: `Document/Plan/ConceptArt/00_ArtDirection.md`  
관련 문서: `Document/Plan/ConceptArt/01_DecisionChecklist.md`, `Document/Plan/ConceptArt/02_ComplexityBudget.md`  
관련 범위: 차량 카메라 거리, 실루엣 가독성, 디테일 표시 기준, AI 원화 검수 기준

---

## 1. 문서 목적

이 문서는 CarFight 차량 원화에서 **카메라 거리 기준으로 어떤 디테일을 살리고 어떤 디테일을 버릴지**를 정의한다.

CarFight는 1인 개발 프로젝트이며, 차량 원화는 실제 게임에서 보이는 정보만 우선해야 한다.  
가까이 확대해서 볼 때 멋진 디테일이라도, 실제 플레이 카메라에서 거의 보이지 않는다면 초기 차량 리소스의 메쉬 디테일로 만들지 않는다.

이 문서의 목적은 다음과 같다.

- 차량이 게임 카메라에서 어떻게 읽혀야 하는지 정한다.
- 원화에서 필요한 디테일과 불필요한 디테일을 구분한다.
- 차량 실루엣, 장갑, 하드포인트, 무기 마운트의 가독성 기준을 정한다.
- AI 이미지 생성 결과가 실제 게임 카메라에 맞는지 검수할 기준을 만든다.
- 1인 개발에서 제작 비용이 큰 작은 디테일을 줄이는 판단 기준을 만든다.

---

## 2. 최상위 기준

이 문서의 최상위 기준은 다음과 같다.

```text
실제 플레이 카메라에서 읽히지 않는 디테일은 기본 메쉬 디테일로 만들지 않는다.
```

CarFight 차량 원화는 감상용 자동차 렌더링이 아니다.  
실제 게임에서 차량은 움직이고, 회전하고, 사격하고, 피격되고, 화면 안에서 다른 차량이나 배경과 함께 보인다.

따라서 원화의 우선순위는 다음과 같다.

```text
차급 실루엣 → 전투 장착부 → 큰 장갑 구조 → 색상 대비 → 작은 표면 디테일
```

작은 표면 디테일은 마지막이다.

---

## 3. 현재 전제

현재 CarFight의 정확한 최종 카메라 값은 아직 확정되지 않은 것으로 본다.  
따라서 이 문서는 고정 미터 단위보다 **가독성 단계**를 먼저 정의한다.

현재 기준 전제는 다음과 같다.

| 항목 | 전제 |
|---|---|
| 기본 플레이 시점 | 차량 후방 3인칭 카메라 |
| 전투 상황 | 차량이 계속 움직이는 중거리 교전 |
| 주요 확인 대상 | 내 차량, 적 차량, 터렛/무기 방향, 장갑 실루엣 |
| 원화 목적 | 감상용 렌더보다 게임 중 식별 우선 |
| 디테일 판단 | 카메라에서 읽히는 크기 기준 |

이 문서는 카메라 시스템이 확정되면 v0.2에서 수치 보정을 할 수 있다.

---

## 4. 카메라 거리 단계

CarFight 원화 검수에서는 차량을 세 거리 단계로 나눠 본다.

| 단계 | 이름 | 용도 | 원화 판단 기준 |
|---|---|---|---|
| R0 | Close Inspect | 가까운 확인 거리 | 쇼케이스/차고/선택 화면용 |
| R1 | Gameplay Mid | 기본 플레이 거리 | 실제 게임 기준의 핵심 거리 |
| R2 | Combat Far | 원거리 전투 거리 | 적 차량 식별과 실루엣 중심 |

CarFight의 기본 원화 기준은 **R1 Gameplay Mid**이다.

```text
기본 기준: R1 Gameplay Mid
```

R0는 멋을 확인하는 거리이고, R2는 전투 가독성을 확인하는 거리다.  
하지만 기본 차량 메쉬를 만들 때는 R1에서 보이는 정보만 우선한다.

---

## 5. R0 - Close Inspect 기준

R0는 가까이 보는 거리다.

사용 상황:

- 차고 화면
- 차량 선택 화면
- 원화 검토
- 모델링 검수
- 홍보 이미지
- 3/4 뷰 콘셉트 이미지

R0에서 보이면 좋은 정보:

- 큰 장갑판의 두께
- 라이트 형태
- 창문 형태
- 타이어 패턴의 큰 방향성
- 센서 렌즈 위치
- 터렛 마운트의 구조
- 색상/마킹/오염 디테일

하지만 중요한 점은 다음이다.

```text
R0에서만 보이는 작은 디테일은 C1 기본 메쉬 기준에 포함하지 않는다.
```

예시:

| R0에서 보이는 요소 | C1 처리 기준 |
|---|---|
| 작은 볼트 | 텍스처/노멀 |
| 작은 스크래치 | 텍스처 |
| 작은 경고 라벨 | 텍스처 |
| 얇은 패널 라인 | 텍스처/노멀 |
| 미세한 금속 결 | 머티리얼 |
| 작은 케이블 | 기본 제외 |

---

## 6. R1 - Gameplay Mid 기준

R1은 CarFight의 가장 중요한 기준 거리다.

사용 상황:

- 기본 주행
- 일반 교전
- 조준/락온 확인
- 터렛 방향 확인
- 피격 상황 확인
- 차량 간 거리 판단

R1에서 반드시 읽혀야 하는 정보:

| 정보 | 이유 |
|---|---|
| 차급 실루엣 | 차량 종류를 빠르게 구분해야 함 |
| 앞/뒤 방향 | 주행 방향과 교전 방향을 알아야 함 |
| 휠 위치 | 차량 움직임과 접지감을 읽어야 함 |
| 루프 마운트 | 무기 장착 여부를 알아야 함 |
| 터렛 방향 | 공격 방향을 알아야 함 |
| 큰 장갑판 | 방어형/개조형 인상을 줘야 함 |
| 큰 색상 영역 | 피아식별/차량 개성에 도움 |
| 큰 발광 포인트 | 센서/전자장비 느낌을 전달 |

R1에서 버려도 되는 정보:

| 정보 | 처리 기준 |
|---|---|
| 작은 볼트 | 보이지 않으므로 텍스처 처리 |
| 작은 라벨 | 차량 선택 화면용 텍스처로만 처리 |
| 얇은 케이블 | 거의 보이지 않으므로 제외 |
| 미세한 패널 라인 | 노멀/텍스처 처리 |
| 작은 스크래치 | 텍스처 처리 |
| 복잡한 내부 구조 | 기본 제외 |

R1에서의 핵심 판단:

```text
차량을 2~3초 보는 동안 차급, 방향, 무장 여부가 읽히면 충분하다.
```

---

## 7. R2 - Combat Far 기준

R2는 전투 중 멀리 있는 차량을 보는 거리다.

사용 상황:

- 원거리 교전
- 빠르게 지나가는 적 차량 확인
- 카메라 줌 없이 목표 인식
- 미니맵/락온 전 차량 식별
- 배경 오브젝트와 차량 구분

R2에서 반드시 읽혀야 하는 정보:

| 정보 | 이유 |
|---|---|
| 전체 덩어리 | 차량인지 배경물인지 구분해야 함 |
| 차급 대략 | 소형/중형/대형 정도는 읽혀야 함 |
| 큰 지붕 윤곽 | 세단/SUV/밴 등 구분에 중요 |
| 휠 위치 덩어리 | 차량임을 인식하는 핵심 요소 |
| 큰 무기 실루엣 | 무장 여부 확인 |
| 큰 색상 대비 | 적/아군 또는 차량 그룹 구분 |

R2에서는 작은 디테일이 거의 의미 없다.

```text
R2 기준에서 보이지 않는 것은 기본 메쉬 복잡도를 늘릴 이유가 아니다.
```

---

## 8. 화면 점유율 기준

정확한 카메라 수치가 확정되기 전까지, 차량의 화면 점유율을 기준으로 검수한다.

| 화면 속 차량 크기 | 판정 | 필요한 정보 |
|---|---|---|
| 화면 폭의 40% 이상 | R0에 가까움 | 형태 검수와 색상 확인 |
| 화면 폭의 15~40% | R1 기준 | 기본 게임 가독성 |
| 화면 폭의 5~15% | R2 기준 | 실루엣과 큰 색상만 중요 |
| 화면 폭의 5% 미만 | 원거리 표식 필요 | 메쉬 디테일보다 UI/효과가 중요 |

CarFight 기본 차량 원화는 다음 범위를 우선한다.

```text
화면 폭의 15~40%에서 읽히는 디자인
```

즉, 원화에서 세부 묘사를 많이 넣어도 화면 폭 15~40%에서 읽히지 않는다면 기본 C1 메쉬 디테일로 만들지 않는다.

---

## 9. 실루엣 가독성 기준

차량 실루엣은 디테일보다 먼저 읽혀야 한다.

### 9.1 옆면 실루엣

Side View에서 가장 먼저 검수한다.

필수 확인 요소:

- 보닛 길이
- 캐빈 위치
- 루프 높이
- 트렁크/후방 적재 공간
- 휠베이스
- 앞/뒤 오버행
- 루프 마운트 위치

옆면 실루엣에서 차급이 읽히지 않으면, 장갑이나 무기를 추가하기 전에 기본 차체를 다시 잡는다.

---

### 9.2 정면 실루엣

Front View에서는 차량의 폭과 높이 인상을 확인한다.

필수 확인 요소:

- 전면 폭
- 차체 높이
- 휠 간격
- 범퍼 보강대
- 전면 장갑판
- 전면 라이트 위치
- 전면 센서 위치

정면에서 너무 복잡한 장식이 많으면, 전투 중 차량 방향이 읽히기 어렵다.

---

### 9.3 후면 실루엣

Rear View에서는 추격 상황에서의 식별성을 확인한다.

필수 확인 요소:

- 후면 폭
- 테일라이트 위치
- 후면 장갑판
- 후면 범퍼
- 후면 냉각구/배기구
- 차량 높이

후면은 플레이 중 자주 보일 가능성이 높기 때문에, 너무 밋밋하면 안 되지만 작은 디테일을 과하게 넣을 필요도 없다.

---

### 9.4 상면 실루엣

Top View에서는 무기 장착과 차체 비례를 확인한다.

필수 확인 요소:

- 루프 마운트 위치
- 터렛 회전 공간
- 차체 폭
- 휠 위치
- 장갑판 돌출 정도
- 전방/후방 방향성

Top View는 모델링과 하드포인트 배치에 중요하다.

---

## 10. 카메라 기준 디테일 분류

디테일은 카메라 기준으로 4단계로 나눈다.

| 등급 | 이름 | 처리 기준 |
|---|---|---|
| D0 | Silhouette Detail | 반드시 메쉬로 표현 |
| D1 | Gameplay Detail | C1 기준에서 메쉬 가능 |
| D2 | Inspect Detail | 텍스처/노멀/머티리얼 우선 |
| D3 | Noise Detail | 초기 기준에서 제외 |

---

### 10.1 D0 - Silhouette Detail

D0는 실루엣을 바꾸는 큰 디테일이다.

메쉬로 만들어야 한다.

예시:

- 차체 큰 형태
- 휠
- 루프 마운트
- 터렛
- 큰 장갑판
- 큰 범퍼 보강대
- 큰 휠가드
- 큰 센서 박스

D0는 R2에서도 어느 정도 읽혀야 한다.

---

### 10.2 D1 - Gameplay Detail

D1은 R1에서 보이는 중간 디테일이다.

대부분 메쉬로 만들 수 있지만, 파츠 예산을 초과하면 단순화한다.

예시:

- 라이트 하우징
- 큰 흡기구
- 큰 배기구
- 큰 문 경계
- 중간 크기 장갑 고정 구조
- 큰 냉각 패널
- 단순 사이드미러

D1은 차량마다 모두 넣을 필요는 없다.  
차량 개성을 만드는 요소 2~4개 정도만 선택한다.

---

### 10.3 D2 - Inspect Detail

D2는 가까이 보면 보이지만, 플레이 중에는 크게 중요하지 않은 디테일이다.

기본적으로 텍스처/노멀/머티리얼로 처리한다.

예시:

- 작은 볼트
- 얇은 패널 라인
- 작은 스크래치
- 작은 라벨
- 정비용 숫자
- 작은 용접 자국
- 미세한 그릴 구멍
- 작은 경고 마킹

D2를 메쉬로 만들면 C1 기준을 쉽게 초과한다.

---

### 10.4 D3 - Noise Detail

D3는 화면에서 노이즈처럼 보이는 디테일이다.

초기 기준에서는 제외한다.

예시:

- 얇은 케이블 다발
- 작은 안테나 여러 개
- 복잡한 기계식 링크
- 실제 차량 내부 구조
- 너무 많은 작은 장갑판
- 복잡한 서스펜션 노출
- 엔진룸 내부 파츠

D3는 원화에서 멋있어 보여도 게임 리소스 제작에는 부담이 크다.

---

## 11. 차량 방향성 가독성

플레이 중에는 차량의 앞/뒤가 빨리 읽혀야 한다.

전면 특징:

- 헤드라이트 또는 센서 라인
- 전면 범퍼 형태
- 보닛 방향
- 전면 장갑판
- 터렛 기본 전방 방향 표시

후면 특징:

- 테일라이트
- 후면 범퍼
- 후면 냉각구/배기구
- 트렁크/적재 공간
- 후면 장갑판

중요 기준:

```text
전면과 후면은 색상, 라이트, 큰 형태 중 최소 2개 요소로 구분되어야 한다.
```

---

## 12. 무기/터렛 가독성

CarFight는 차량 전투 게임이므로 무기 방향이 중요하다.

터렛과 무기 원화는 다음을 지킨다.

| 항목 | 기준 |
|---|---|
| 터렛 크기 | 차량보다 먼저 읽히면 안 됨 |
| 총열 방향 | R1에서 방향이 읽혀야 함 |
| 루프 마운트 | 차량 중앙 또는 명확한 위치에 있어야 함 |
| 회전 공간 | Top View에서 방해 요소가 적어야 함 |
| 무기 실루엣 | 기관포/미사일/센서형 등 큰 차이는 읽혀야 함 |
| 작은 부품 | 대부분 텍스처 또는 생략 |

권장 기준:

```text
무기는 차량의 역할을 보여주되, 차량 실루엣을 압도하지 않는다.
```

## 13. 색상 가독성

카메라 거리에서는 작은 형태보다 큰 색면이 더 잘 보인다.

따라서 차량 원화는 색상도 가독성 기준으로 본다.

권장 기준:

| 요소 | 기준 |
|---|---|
| 기본 차체색 | 큰 면으로 유지 |
| 장갑판 색 | 차체와 약간 구분 |
| 유리 색 | 어둡게 단순 처리 |
| 발광 색 | 제한적 포인트로만 사용 |
| 경고 마킹 | 큰 면 위에 소량만 사용 |
| 작은 라벨 | R0용 텍스처로 제한 |

색상 기준 문장:

```text
멀리서 보이는 것은 작은 선이 아니라 큰 명암 덩어리다.
```

## 14. AI 원화 검수 기준

AI 이미지 생성 결과는 아래 기준으로 검수한다.

### 14.1 통과 기준

- 축소해서 봐도 차급이 읽힌다.
- 앞/뒤 방향이 읽힌다.
- 루프 마운트나 무기 위치가 보인다.
- 큰 장갑판이 보인다.
- 작은 디테일이 많아도 메쉬로 만들 필요는 없어 보인다.
- 차량 하나의 주요 덩어리가 10~16개 파츠로 나뉠 수 있어 보인다.
- 실제 브랜드 차량처럼 보이지 않는다.

### 14.2 탈락 기준

- 확대해서 봐야만 멋이 보인다.
- 축소하면 차급이 사라진다.
- 장갑판이 너무 잘게 나뉘어 있다.
- 무기가 차량보다 먼저 보인다.
- 실제 차량의 복잡한 패널 라인을 너무 많이 닮았다.
- 작은 기계 부품이 전체 인상을 지배한다.
- 전면과 후면 구분이 어렵다.

AI 원화 검수 기본 문장:

```text
작게 봤을 때 좋아 보이지 않는 차량은 게임 카메라에서도 좋지 않다.
```

## 15. 원화 시트 축소 검수

모든 차량 원화는 축소 검수를 한다.

권장 검수 방식:

1. 원화를 전체 크기로 본다.
2. 50% 크기로 줄여 본다.
3. 25% 크기로 줄여 본다.
4. 10% 크기 또는 썸네일 크기로 본다.
5. 차급, 방향, 무장 여부가 읽히는지 확인한다.

축소 검수에서 읽혀야 하는 순서:

```text
차량 종류 → 앞/뒤 방향 → 무장 여부 → 장갑 개조 → 세부 개성
```

25% 이하에서 차급이 읽히지 않으면 실루엣을 다시 잡는다.
