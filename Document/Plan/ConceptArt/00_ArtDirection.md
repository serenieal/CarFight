# CarFight Concept Art - Art Direction

문서 버전: v0.5    
작성일: 2026-07-06  
문서 위치: `Document/Plan/ConceptArt/00_ArtDirection.md`  
관련 범위: 차량 원화, 부품 원화, 무기 장착부 원화, 3D 메쉬 제작 기준

---

## 1. 문서 목적

이 문서는 CarFight의 리소스 메쉬 제작을 위한 원화 작업 전에 공통으로 적용할 **아트 방향성**을 정리한다.

원화 작업의 목적은 단순히 보기 좋은 이미지를 만드는 것이 아니라, 이후 3D 모델링, 언리얼 엔진 적용, 차량 파츠 분리, 무기 장착, 머티리얼 제작까지 이어질 수 있는 **제작 기준선**을 만드는 것이다.

CarFight는 1인 개발 프로젝트이며, 현재 개발자는 모델링 전문 지식이 거의 없는 상태를 전제로 한다.  
따라서 원화는 고난도 모델링을 유도하는 리얼한 디테일보다, 실제 제작과 수정이 가능한 단순한 형태를 우선해야 한다.

따라서 이 문서의 기준은 다음 작업에 공통으로 적용한다.

- 차량 차체 원화
- 차량 장갑 패널 원화
- 휠, 범퍼, 루프 마운트 등 외장 파츠 원화
- 터렛, 센서, 하드포인트 등 전투 장착부 원화
- AI 모델링 도구에 전달할 형태 기준
- AI 이미지 생성 프롬프트 작성 기준

## 2. 최우선 제작 제약

CarFight 원화의 최우선 제약은 다음과 같다.

```text
AI로 생성한 뒤 1인 개발자가 직접 검수·수정·관리할 수 있는 단순한 형태를 우선한다.
```

이 기준은 모든 원화 판단에서 우선한다.

CarFight는 너무 리얼한 자동차 시뮬레이션 스타일로 가지 않는다.  
현실 차량의 실루엣과 기능적 설득력은 유지하되, 실제 자동차처럼 복잡한 패널 라인, 내부 구조, 엔진룸 디테일, 서스펜션 디테일, 미세한 표면 굴곡까지 따라가지는 않는다.

중요한 방향은 다음과 같다.

| 항목 | 기준 |
|---|---|
| 리얼함 | 현실 기반 실루엣과 기능적 설득력까지만 유지 |
| 디테일 | 필요한 디테일만 남기고 장식성 디테일은 줄임 |
| 형태 | 큰 면, 단순한 덩어리, 읽기 쉬운 실루엣 우선 |
| 모델링 난이도 | AI 생성 결과를 초보자가 검수·수정 가능한 구조 우선 |
| 파츠 수 | 불필요하게 많은 분리 파츠를 만들지 않음 |
| 표면 정보 | 텍스처/머티리얼로 처리 가능한 것은 메쉬 디테일로 만들지 않음 |
| 원화 판단 | 멋있어도 만들기 어렵다면 기본안에서 제외 |

핵심 판단 문장:

```text
원화가 멋있어도 1인 개발자가 모델링하거나 수정하기 어렵다면 CarFight 기본 기준에 맞지 않는다.
```

## 3. 단일 패스 최종 후보 제작 원칙

현재 CarFight는 리소스 제작에 사용할 시간이 부족하다.  
따라서 리소스 하나를 `블록아웃 → 초안 → 디테일업 → 수정 → 최종화`처럼 여러 단계로 나눠 제작하는 방식을 기본으로 삼지 않는다.

CarFight의 기본 리소스 제작 방식은 다음과 같다.

```text
각 리소스는 처음부터 최종 후보로 사용할 수 있는 수준을 목표로 만든다.
```

이 원칙을 이 문서에서는 `Single-Pass Final Asset` 원칙이라고 부른다.

한국어 기준:

```text
단일 패스 최종 후보 제작
```

이 원칙은 다음 의미다.

| 항목 | 기준 |
|---|---|
| 제작 방식 | 여러 단계로 다듬는 방식이 아니라, 처음부터 최종 후보를 목표로 함 |
| 원화 목표 | 감상용 초안이 아니라 메쉬 제작에 바로 쓸 수 있는 정사영 기준을 우선함 |
| AI 생성 목표 | 여러 차례 리파인보다 기준을 강하게 넣은 1차 생성 품질을 우선함 |
| 모델링 목표 | 나중에 대폭 수정하지 않아도 되는 단순 구조를 우선함 |
| 실패 처리 | 복잡한 결과물을 오래 고치기보다 단순 기준으로 다시 생성하거나 교체함 |

### 3.1 AI 모델링 전제

CarFight의 기본 3D 리소스 제작은 수작업 모델링을 기본으로 보지 않는다.  
기본 전제는 다음과 같다.

```text
원화와 프롬프트 기준을 강하게 잡고, AI 모델링 도구로 3D 후보를 생성한 뒤, 1인 개발자가 검수·수정·언리얼 적용 가능한 형태만 채택한다.
```

따라서 이 문서에서 말하는 제작 가능성은 다음 의미다.

| 항목 | 기준 |
|---|---|
| 생성 가능성 | AI 모델링 도구가 큰 형태를 혼동하지 않아야 함 |
| 검수 가능성 | 생성 결과의 차급, 파츠, 머티리얼 오류를 사람이 빠르게 판단할 수 있어야 함 |
| 수정 가능성 | 위치, 크기, 색상, 파츠 분리 정도를 초보자도 조정할 수 있어야 함 |
| 적용 가능성 | 언리얼에서 피벗, 콜리전, 머티리얼, LOD를 정리할 수 있어야 함 |

중요 기준:

```text
AI가 한 번에 완벽한 모델을 만든다고 가정하지 않는다. 대신 AI 결과가 단순해서 검수와 후처리가 가능해야 한다.
```

중요한 예외:

```text
C0/C1/C2는 리소스 하나를 순서대로 제작하는 단계가 아니라, 복잡도와 검수 등급이다.
```

즉, 실제 차량 리소스마다 C0를 만들고, 그다음 C1로 올리고, 다시 C2로 다듬는 과정을 기본으로 하지 않는다.  
기본 차량 리소스는 처음부터 **C1 Simple Game Asset 최종 후보**를 목표로 만든다.

## 4. 핵심 아트 방향성

CarFight의 기본 아트 방향성은 다음과 같이 정의한다.

> 현실 기반 민간 차량 실루엣을 바탕으로, 단순화된 근미래 전투용 장갑과 무기 장착 구조가 추가된 차량 디자인.

CarFight의 차량은 처음부터 군용 장갑차처럼 보여서는 안 된다.  
기본 인상은 **일반 도로에서 볼 수 있는 민간 차량**이어야 하며, 그 위에 전투용 개조가 추가된 형태여야 한다.

다만 일반 차량을 지나치게 사실적으로 복제하지 않는다.  
차급을 알아볼 수 있는 큰 실루엣만 유지하고, 실제 차량의 복잡한 디테일은 게임 리소스로 제작 가능한 수준까지 줄인다.

즉, 플레이어가 차량을 봤을 때 다음 순서로 인식되는 것이 이상적이다.

1. 먼저 차급이 읽힌다.
2. 그다음 전투 개조가 보인다.
3. 마지막으로 필요한 근미래 장비와 기능 요소가 보인다.

예시 인식 순서:

```text
소형 해치백이다 → 단순한 장갑 패널이 붙어 있다 → 루프에 터렛 마운트가 준비되어 있다
```

```text
왜건이다 → 후방 적재 공간이 강화되어 있다 → 센서와 냉각부가 단순한 형태로 추가되어 있다
```

## 4. 추천 스타일 이름

현재 CarFight의 원화 스타일은 다음 이름으로 부른다.

```text
Simplified Near-Future Civilian Combat Car
```

한국어 기준으로는 다음 의미다.

```text
단순화된 근미래 민간 차량 개조 전투차
```

이 스타일명은 이후 AI 프롬프트, 문서, 원화 시트, 레퍼런스 정리에서 공통 키워드로 사용한다.

## 5. 유지해야 할 디자인 요소

CarFight 원화에서 유지해야 하는 요소는 다음과 같다.

| 항목 | 기준 |
|---|---|
| 기본 차체 | 현실 기반 민간 차량 실루엣 |
| 차급 실루엣 | Microcar, City Car, Compact, Sedan, SUV 등 차급이 먼저 읽혀야 함 |
| 단순화 | 실제 차량 디테일을 그대로 복제하지 않고 제작 가능한 수준으로 정리 |
| 전투 개조 | 기존 차량에 추가된 장갑, 센서, 마운트처럼 보여야 함 |
| 장갑 표현 | 복잡한 장갑 구조보다 큰 판형 패널 중심 |
| 무기 장착부 | 루프, 범퍼, 측면 등 실제 부착 가능한 구조 중심 |
| 분위기 | 저채도, 기능적, 산업적, 약간의 사이버펑크 감성 |
| 제작성 | 3D 메쉬로 만들기 쉬운 큰 형태와 명확한 면 분할 |
| 수정성 | 나중에 초보자도 크기, 위치, 파츠를 바꿀 수 있는 구조 |

## 6. 피해야 할 디자인 요소

CarFight 원화에서 피해야 하는 요소는 다음과 같다.

| 항목 | 피해야 하는 이유 |
|---|---|
| 완전한 군용 장갑차 | CarFight의 핵심은 민간 차량 개조 전투차이기 때문 |

| 너무 복잡한 세부 장식 | 1인 개발 환경에서 모델링, UV, 머티리얼 작업 부담 증가 |
| 비현실적인 변형 구조 | 초기 리소스 제작과 게임 시스템 구현 범위를 초과함 |
| 얇고 많은 돌출 부품 | 충돌체, LOD, 파손 처리, 시야 가독성에서 불리함 |

## 7. 민간 차량 기반 규칙

원화의 첫 단계에서는 항상 **기본 민간 차량 실루엣**을 먼저 잡는다.

차량 원화 작업 순서는 다음을 기본으로 한다.

1. 차급을 정한다.
2. 민간 차량 기준의 큰 실루엣을 잡는다.
3. 실제 차량 디테일을 단순화한다.
4. 전투 개조 부위를 정한다.
5. 장갑 패널을 큰 판형으로 추가한다.
6. 무기 또는 터렛 마운트 위치를 잡는다.
7. 센서, 냉각구, 배터리 박스 등 근미래 기능 요소를 필요한 만큼만 추가한다.
8. 세부 장식은 마지막에 최소한으로 더한다.

중요한 기준:

```text
전투 요소는 차체를 대체하는 것이 아니라, 차체 위에 추가되는 단순한 구조여야 한다.
```

## 8. 단순화 기준

CarFight 원화는 의도적으로 단순화한다.

단순화는 품질을 낮추는 것이 아니라, 1인 개발에서 완성 가능성을 높이기 위한 제작 전략이다.

### 8.1 메쉬로 만들 디테일

다음 요소는 메쉬로 만들어도 된다.

- 큰 장갑판
- 범퍼 보강대
- 루프 터렛 마운트
- 단순한 휠가드
- 큰 흡기구 또는 배기구
- 큰 센서 박스
- 단순한 배터리/전자장비 박스
- 명확한 문, 보닛, 트렁크 경계

### 8.2 텍스처나 머티리얼로 처리할 디테일

다음 요소는 가능하면 메쉬가 아니라 텍스처나 머티리얼로 처리한다.

- 작은 볼트
- 얇은 패널 라인
- 작은 스크래치
- 표면 오염
- 경고 라벨
- 미세한 금속 결
- 작은 용접 자국
- 얇은 네온 라인
- 작은 정비용 마킹

### 8.3 기본적으로 제외할 디테일

다음 요소는 초기 원화 기준에서 제외한다.

- 실제 자동차 하부 구조 재현
- 복잡한 서스펜션 노출 구조
- 엔진룸 내부 디테일
- 열리는 문/보닛/트렁크를 전제로 한 내부 구조
- 얇은 안테나 다발
- 복잡한 케이블 묶음
- 수십 개의 작은 외장 파츠
- 비대칭 디테일이 과하게 많은 차체

## 9. 사이버펑크 감성 적용 기준

CarFight는 사이버펑크 감성을 사용할 수 있지만, 네온 장식 중심의 화려한 사이버펑크를 기본값으로 삼지 않는다.

추천 방향은 다음에 가깝다.

```text
저예산 개조 레이싱 차량 + 근미래 용병 차량 + 단순한 산업 장갑 패널
```

사이버펑크 요소는 다음 정도로 제한한다.

- 작은 상태 표시등
- 센서 렌즈
- 카메라 모듈
- 냉각부의 약한 발광
- 배터리/전자장비 상태 표시 패널
- 번호, 경고 마킹, 정비용 라벨

피해야 할 방향:

- 차체 전체를 덮는 과도한 네온 라인
- 기능 설명이 어려운 장식용 발광 부품
- 실제 제작하기 어려운 복잡한 홀로그램 장치
- 게임 메쉬에서 표현하기 어려운 얇고 많은 장식선

## 10. 3D 메쉬 제작 관점의 기준

원화는 3D 메쉬 제작을 전제로 그려야 한다.

따라서 원화에서 다음 기준을 지킨다.

| 기준 | 설명 |
|---|---|
| 큰 덩어리 우선 | 멀리서 봐도 차급과 역할이 읽혀야 함 |
| 명확한 면 분할 | 장갑판, 문, 범퍼, 루프 마운트의 경계가 분명해야 함 |
| 적은 파츠 수 | 차량 하나가 너무 많은 독립 메쉬로 나뉘지 않아야 함 |
| 반복 가능한 부품 | 휠가드, 패널, 센서 등은 재사용 가능한 형태가 좋음 |
| 피벗 예측 가능성 | 휠, 터렛 등 움직일 가능성이 있는 부품은 중심축이 명확해야 함 |
| 충돌체 단순화 | 실제 콜리전은 단순 박스/캡슐/컨벡스 형태로 근사 가능해야 함 |
| 언리얼 적용성 | 머티리얼 슬롯, LOD, 나나이트 적용 여부를 고려해야 함 |
| 수정 가능성 | 초보자도 에디터나 모델링 툴에서 위치/크기 수정이 가능해야 함 |

---

## 11. 첫 번째 기준 문장

앞으로 CarFight 원화 작업에서 최상위 기준 문장으로 다음을 사용한다.

```text
CarFight의 차량은 현실 기반 민간 차량 실루엣을 가진 단순화된 근미래 전투 개조 차량이며, 1인 개발자가 제작·수정 가능한 형태를 최우선으로 한다.
```

보조 기준 문장:

```text
차량은 차급 실루엣이 먼저 읽혀야 하며, 전투 개조는 기능적인 부착물처럼 보이되 복잡한 리얼 디테일은 최소화한다.
```

## 14. Changelog

### v0.5

- 3D 리소스 제작의 기본 전제가 수작업 모델링이 아니라 AI 모델링 후보 생성이라는 점을 명시했다.
- 제작 가능성을 AI 생성 가능성, 검수 가능성, 수정 가능성, 언리얼 적용 가능성으로 재해석했다.
- 직접 모델링 중심으로 읽힐 수 있는 표현을 AI 생성 결과 검수·수정 중심으로 조정했다.

### v0.4

- 시간이 부족해 리소스 하나를 여러 제작 단계로 나눌 수 없다는 제약을 반영했다.
- `Single-Pass Final Asset` / `단일 패스 최종 후보 제작` 원칙을 추가했다.
- C0/C1/C2를 실제 리소스별 순차 제작 단계가 아니라 복잡도와 검수 등급으로 재해석했다.
- 기본 차량 리소스는 처음부터 C1 Simple Game Asset 최종 후보를 목표로 만든다고 명시했다.

### v0.3

- `01_DecisionChecklist.md` 생성에 맞춰 다음 문서 예정 목록을 갱신했다.
- 원화 기준 결정 순서를 제작 난이도, 카메라 가독성, 차급, 실루엣, 비례, 장갑, 하드포인트 순서로 세분화했다.
- 기존 `01_TechLevel.md` 중심의 예정 목록을 1인 개발 제작성 중심의 체크리스트 구조로 조정했다.

### v0.2

- 사용자의 핵심 제작 제약을 반영했다.
- CarFight 원화가 지나치게 리얼한 자동차 시뮬레이션 방향으로 가지 않는다고 명시했다.
- 1인 개발, 모델링 지식 부족, 직접 수정 난이도 문제를 최우선 제작 제약으로 추가했다.
- 스타일명을 `Near-Future Civilian Combat Car`에서 `Simplified Near-Future Civilian Combat Car`로 갱신했다.
- 메쉬로 만들 디테일, 텍스처/머티리얼로 처리할 디테일, 초기 제외 디테일 기준을 추가했다.
- 최상위 기준 문장을 “제작·수정 가능한 단순화” 중심으로 갱신했다.

### v0.1

- CarFight 원화 작업의 최상위 아트 방향성 정의.
- `Near-Future Civilian Combat Car` 스타일명 추가.

## 15. Migration

### v0.5 적용 시 기존 작업 영향

- 기존 ConceptArt 문서의 `모델링 난이도`, `제작 가능성`, `수정 가능성` 표현은 수작업 모델링만 뜻하지 않는다.
- 앞으로 차량 원화와 프롬프트는 AI 모델링 도구가 단순한 파츠 구조로 해석할 수 있는지를 함께 검수한다.
- AI 모델링 결과가 복잡하거나 파츠 구분이 흐리면 오래 수작업 수정하지 않고 더 단순한 프롬프트로 재생성한다.
- 언리얼 적용 전에는 생성 결과의 피벗, 콜리전 가능성, 머티리얼 슬롯, LOD 단순화를 반드시 확인한다.

### v0.4 적용 시 기존 작업 영향

- 앞으로 리소스 하나를 여러 제작 단계로 나눠 완성하는 방식을 기본 워크플로우로 보지 않는다.
- 기존 C0/C1/C2 표현은 제작 순서가 아니라 복잡도와 검수 기준으로 해석한다.
- 새 차량 리소스는 처음부터 C1 Simple Game Asset 최종 후보를 목표로 원화/AI 생성/모델링 기준을 잡는다.
- 복잡한 결과물을 오래 수정하는 방식보다, 단순 기준을 만족하는 결과물을 다시 생성하거나 교체하는 방식을 우선한다.

### v0.3 적용 시 기존 작업 영향

- `01_DecisionChecklist.md`가 원화 기준 문서 작성 순서의 기준 문서가 된다.
- 이후 문서 작성 순서는 `00_ArtDirection.md`의 예정 목록과 `01_DecisionChecklist.md`의 결정 문서 작성 순서를 함께 따른다.
- 기존에 계획했던 `01_TechLevel.md`는 독립 1순위 문서가 아니라, 제작 난이도와 차급/실루엣 기준을 정한 뒤 필요한 경우 하위 주제로 다룬다.

### v0.2 적용 시 기존 작업 영향

- v0.1에서 사용한 `현실적인 민간 차량` 표현은 `현실 기반 민간 차량 실루엣`으로 해석한다.
- 앞으로 생성되는 차량 원화는 실제 차량 디테일을 많이 따라가는 방향보다, 차급을 알아볼 수 있는 단순화된 큰 형태를 우선한다.
- AI 이미지 생성 프롬프트에는 다음 성격을 추가해야 한다.
  - simplified design
  - clean readable shapes
  - low modeling complexity
  - large simple armor panels
  - no excessive realistic detail
- 이미 만들어진 차량 이미지 또는 AI 생성 결과가 있다면, 다음 기준으로 재검토한다.
  - 1인 개발자가 모델링하거나 수정할 수 있는 수준인가?
  - 작은 디테일이 메쉬로 너무 많이 들어가 있지 않은가?
  - 실제 차량처럼 복잡한 패널 라인이 과하지 않은가?
  - 텍스처로 처리할 수 있는 정보가 메쉬 형태로 과하게 들어가 있지 않은가?

### v0.1 적용 시 기존 작업 영향

- 아직 확정된 차량 원화 기준 문서가 없으므로 기존 문서 마이그레이션은 필요 없다.
- 이후 생성되는 차량/무기/부품 원화는 이 문서의 아트 방향성을 기본값으로 따른다.
- 이미 만들어진 차량 이미지 또는 AI 생성 결과가 있다면, 다음 기준으로 재검토한다.
  - 민간 차량 차급 실루엣이 먼저 읽히는가?
  - 전투 요소가 차체 자체가 아니라 부착물처럼 보이는가?
  - 군용 장갑차나 탱크에 너무 가까워지지 않았는가?
  - 3D 메쉬로 만들기 어려울 정도로 장식이 과하지 않은가?
