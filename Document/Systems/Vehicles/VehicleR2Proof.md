## What is implemented

`UE/Source/CarFight_ReEditor/Private/DataAuthoring/CFVehicleAuthoringToolset.h/.cpp`:
- Retain `PreviewVehicleRecordIdentity(VehicleId)` as R0.
- Add `CreateNewVehicleRecords(request_json, gopymcp_execution_proof)` as a UE5.8 `AICallable` static Toolset function.
- Only `request_json={"VehicleId":"<ASCII canonical id>"}` (one key) is accepted. No caller-submitted CallerKind, Boolean, approval hash, path, tool URL, or project ID can extend authority.
- Canonical package/object names come from `FCFVehicleRecordIdentity::BuildDefaultIdentity`.
- Before any mutation, redeem one-use Bridge proof against trusted loopback `/internal/ue-execution-proof/claim`. Invalid or missing proof returns `ExecutionProofRejected`. Token and raw input are not included in the result.
- After successful claim, run existing `PreviewAIVehicleRecords` and pass fresh scope hash to a **private** `FCFVehicleAuthoringService::CreateTrustedAIVehicleRecords`. This delegates to the same internal `CreateVehicleRecordsImpl` as legacy `CreateVehicleRecords`; no second asset writer is introduced.
- Return `bSucceeded, ErrorCode, DefinitionPath, RecipePath, bSavePerformed`. New assets are Dirty/Undo-capable, Save0 and unpublished.

`CarFight_ReEditor.Build.cs`: Editor-only `HTTP` dependency in addition to existing `ToolsetRegistry`. The internal verifier uses the **UE 5.8** bounded `IHttpRequest::ProcessRequestUntilComplete` API (up to 2 seconds); no process, shell or Python command is run by the Toolset.
