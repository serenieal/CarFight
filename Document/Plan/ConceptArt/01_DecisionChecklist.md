# CarFight Concept Art - Decision Checklist

문서 버전: v0.4  
작성일: 2026-07-06  
문서 위치: `Document/Plan/ConceptArt/01_DecisionChecklist.md`  
상위 기준 문서: `Document/Plan/ConceptArt/00_ArtDirection.md`  
관련 범위: 원화 기준 결정 순서, 차량/부품/무기 원화 제작 전 체크리스트

---

## 1. 문서 목적

이 문서는 CarFight 원화 작업을 시작하기 전에 **무엇을 먼저 정해야 하는지**를 정리한다.

이 문서는 개별 차량 디자인 문서가 아니다.  
이 문서는 앞으로 생성할 원화 기준 문서들의 **목차이자 결정 체크리스트**이다.

CarFight의 원화 기준은 다음 상위 원칙을 따른다.

```text
CarFight의 차량은 현실 기반 민간 차량 실루엣을 가진 단순화된 근미래 전투 개조 차량이며, 1인 개발자가 제작·수정 가능한 형태를 최우선으로 한다.
```

즉, 이 문서에서 정리하는 모든 결정 항목은 다음 질문을 통과해야 한다.

```text
이 기준이 1인 개발자가 실제로 만들 수 있는 리소스 제작에 도움이 되는가?
```

## 2. 현재 확정된 상위 기준

아래 항목은 이미 `00_ArtDirection.md` v0.2에서 확정된 기준으로 본다.

| 항목 | 확정 기준 |
|---|---|
| 개발 규모 | 1인 개발 기준 |
| 모델링 숙련도 | 모델링 전문 지식이 거의 없는 상태를 전제로 함 |
| 기본 모델링 방식 | AI 모델링 도구로 3D 후보를 생성한 뒤 검수·수정·언리얼 적용 |
| 전체 아트 방향 | 단순화된 근미래 민간 차량 개조 전투차 |
| 리얼함 강도 | 낮음에서 중간 사이 |
| 기본 차체 | 현실 기반 민간 차량 실루엣 |
| 디테일 방향 | 필요한 디테일만 유지 |
| 제작 우선순위 | 제작·수정 가능한 단순 구조 우선 |
| 전투 요소 | 부착형 장갑/무기/센서 중심 |
| 사이버펑크 강도 | 낮음에서 중간 사이 |
| 작은 표면 정보 | 가능하면 텍스처/머티리얼로 처리 |
| 제작 흐름 | 각 리소스는 처음부터 최종 후보로 제작 |

## 3. 원화 기준 결정 원칙

앞으로 원화 기준을 정할 때는 다음 순서를 지킨다.

1. **제작 가능성**을 먼저 본다.
2. 그다음 **게임에서 읽히는 실루엣**을 본다.
3. 그다음 **차량의 역할과 전투 기능**을 본다.
4. 마지막으로 **장식성 디테일**을 본다.

중요한 점은 순서다.

```text
멋있음 → 제작 가능성
```

이 순서가 아니다.

CarFight에서는 다음 순서가 맞다.

```text
제작 가능성 → 실루엣 가독성 → 전투 기능 → 분위기 → 장식
```

추가 제작 흐름 원칙:

```text
리소스 하나를 여러 단계로 다듬는 것이 아니라, 처음부터 최종 후보로 만들 수 있는 기준을 정한다.
```

따라서 앞으로의 기준 문서는 복잡한 후처리나 장기 리파인을 전제로 하지 않는다.  
각 결정은 AI 생성 또는 모델링 결과가 한 번에 C1 최종 후보에 가까워지도록 제약을 명확히 하는 방향으로 작성한다.

추가 AI 모델링 전제:

```text
이 체크리스트의 제작 가능성은 사람이 처음부터 모든 모델을 직접 만든다는 뜻이 아니라, AI 모델링 결과를 혼자 검수하고 고칠 수 있는 수준을 뜻한다.
```

## 4. 결정 우선순위

원화 기준은 한 번에 전부 정하지 않는다.  
아래 우선순위대로 하나씩 결정한다.

| 우선순위 | 결정 범위 | 이유 |
|---|---|---|
| P0 | 제작 난이도 기준 | 1인 개발에서 완성 가능성을 먼저 확보해야 함 |
| P0 | 실루엣/비례 기준 | 차량이 멀리서도 차급별로 읽혀야 함 |
| P0 | 차급 분류 기준 | 차량 리소스 종류와 확장 기준이 됨 |
| P0 | 원화 시트 포맷 | AI 생성, 수작업 보정, 모델링 전달 기준이 됨 |
| P1 | 장갑 패널 규칙 | 전투 개조 느낌을 만드는 핵심 요소 |
| P1 | 하드포인트/마운트 규칙 | 무기 시스템과 직접 연결됨 |
| P1 | 재질/색상 기준 | 에셋 통일감과 머티리얼 제작에 필요 |
| P2 | 마모/손상 기준 | 분위기 강화용. 초기 제작에서는 과하면 부담 |
| P2 | 진영/등급별 변주 | 기본 리소스가 안정된 뒤 확장 |
| P2 | AI 프롬프트 세부 규칙 | 기준 확정 후 자동화 품질 향상용 |

## 5. 반드시 결정해야 할 항목 목록

### 5.1 제작 난이도 등급

가장 먼저 정해야 한다.

이 기준은 원화에서 허용할 디테일의 양을 제한한다.

결정해야 할 것:

- 차량 1대당 허용할 최대 파츠 수
- 메쉬로 만들 디테일과 텍스처로 처리할 디테일의 경계
- 허용할 곡면 복잡도
- 허용할 비대칭 디테일 강도
- 초보자가 수정 가능한 형태의 기준

권장 방향:

```text
Low to Medium Complexity
```

한국어 기준:

```text
낮음에서 중간 사이의 제작 난이도
```

---

### 5.2 카메라 거리 기준

게임에서 차량을 어떤 거리에서 주로 보게 되는지 정해야 한다.

카메라 거리가 정해져야 디테일을 어디까지 넣을지 판단할 수 있다.

결정해야 할 것:

- 기본 플레이 카메라 거리
- 전투 중 차량이 화면에서 차지하는 크기
- 근접 감상용 디테일이 필요한지 여부
- 멀티플레이 또는 원거리 교전에서 필요한 실루엣 가독성

권장 방향:

```text
차량은 중거리에서 가장 잘 읽히도록 디자인한다.
가까이서 보는 세부 디테일보다는 큰 실루엣과 장착 부위 가독성을 우선한다.
```

---

### 5.3 차급 분류 기준

CarFight 차량을 어떤 차급으로 나눌지 정해야 한다.

차급은 단순한 이름이 아니라, 원화와 모델링의 기준이 된다.

결정해야 할 것:

- 사용할 차급 목록
- 각 차급의 대표 실루엣
- 각 차급의 대략적인 길이/폭/높이 비율
- 각 차급의 전투 개조 허용 범위
- 차급별로 유지해야 할 민간 차량 느낌

후보 차급:

| 차급 | 기본 인상 |
|---|---|
| Microcar | 매우 짧고 좁은 초소형 차량 |
| City Car | 도심형 경차 |
| Subcompact | 소형 해치백 |
| Compact | 일반적인 소형/준중형 해치백 |
| Sedan | 낮고 긴 승용차 |
| Coupe | 낮고 날렵한 2도어 스타일 |
| Wagon | 긴 루프와 적재 공간 |
| SUV | 높고 튼튼한 차체 |
| Van | 넓은 박스형 차체 |
| Pickup | 짐칸이 있는 다목적 차량 |

---

### 5.4 실루엣 규칙

차량이 멀리서도 어떤 차급인지 읽히도록 실루엣 규칙을 정해야 한다.

결정해야 할 것:

- 차급별 옆면 실루엣
- 루프 높이와 보닛 길이의 기준
- 앞/뒤 오버행 길이
- 휠베이스 비율
- 전투 개조가 실루엣을 얼마나 바꿀 수 있는지

중요 기준:

```text
전투 개조가 붙어도 원래 차급 실루엣은 유지되어야 한다.
```

---

### 5.5 비례 기준

차량의 길이, 폭, 높이, 휠 크기 비례를 정해야 한다.

결정해야 할 것:

- 차급별 기본 비례
- 휠 크기 기준
- 차체 높이 대비 휠 크기
- 장갑 패널이 추가되어도 과하게 뚱뚱해지지 않는 기준
- 터렛 마운트가 차량 크기에 비해 과하지 않은 기준

권장 방향:

```text
현실 차량보다 약간 더 굵고 단순한 비례를 허용한다.
단, 장난감처럼 과장된 비례는 기본값으로 쓰지 않는다.
```

---

### 5.6 디테일 예산

차량 한 대에 넣을 수 있는 디테일의 양을 정해야 한다.

결정해야 할 것:

- 큰 디테일 수
- 중간 디테일 수
- 작은 디테일 처리 방식
- 메쉬 디테일과 텍스처 디테일의 분리 기준
- 반복 재사용 가능한 디테일 종류

권장 기준:

| 디테일 크기 | 처리 방식 |
|---|---|
| 큰 디테일 | 메쉬로 제작 |
| 중간 디테일 | 상황에 따라 메쉬 또는 노멀/텍스처 처리 |
| 작은 디테일 | 가능하면 텍스처/머티리얼 처리 |

예시:

| 요소 | 권장 처리 |
|---|---|
| 큰 장갑판 | 메쉬 |
| 루프 마운트 | 메쉬 |
| 휠가드 | 메쉬 |
| 작은 볼트 | 텍스처/노멀 |
| 얇은 패널 라인 | 텍스처/노멀 |
| 스크래치 | 텍스처 |
| 경고 라벨 | 텍스처 |

---

### 5.7 모듈화 기준

차량을 어느 정도까지 모듈형으로 만들지 정해야 한다.

결정해야 할 것:

- 차체와 휠은 반드시 분리할지
- 장갑판을 별도 파츠로 둘지 차체와 합칠지
- 터렛 마운트를 모든 차량에 공통 규격으로 둘지
- 범퍼/휠가드/센서를 공용 파츠로 만들지
- 1인 개발자가 관리 가능한 모듈 수의 상한

권장 방향:

```text
처음부터 완전한 모듈형 차량 시스템을 목표로 하지 않는다.
공용화 가치가 큰 부품만 제한적으로 모듈화한다.
```

우선 모듈화 후보:

- 휠
- 루프 터렛 마운트
- 단순 장갑판
- 범퍼 보강대
- 센서 박스
- 무기 장착 하드포인트

---

### 5.8 장갑 패널 규칙

전투 개조 느낌을 만드는 장갑 패널 규칙을 정해야 한다.

결정해야 할 것:

- 장갑판의 기본 형태
- 장갑판 두께 표현 방식
- 차급별 장갑 허용량
- 장갑판을 차체에 붙이는 방식
- 장갑판과 문/창문/휠의 관계

권장 방향:

```text
장갑판은 복잡한 군용 장갑 구조가 아니라, 큰 판형 패널을 덧댄 느낌으로 시작한다.
```

피해야 할 것:

- 너무 많은 작은 장갑 조각
- 겹겹이 쌓인 복잡한 장갑 구조
- 차량 원래 실루엣을 완전히 덮는 장갑
- 모델링하기 어려운 곡면 장갑

---

### 5.9 하드포인트/마운트 규칙

무기와 장비를 어디에 붙일지 정해야 한다.

결정해야 할 것:

- 루프 마운트 기본 위치
- 전방/후방/측면 하드포인트 허용 여부
- 차급별 하드포인트 수
- 하드포인트 크기 등급
- 터렛 회전 반경을 방해하지 않는 실루엣 기준

권장 방향:

```text
초기에는 루프 중앙 마운트를 기본으로 한다.
측면/전방/후방 마운트는 기본 시스템이 안정된 뒤 확장한다.
```

---

### 5.10 무기 원화 기준

차량용 무기 원화의 단순화 기준도 필요하다.

결정해야 할 것:

- 터렛 크기 기준
- 총열 길이 기준
- 미사일/로켓/기관포/레이저 등 무기군 허용 여부
- 무기별 실루엣 차이
- 무기 파츠 수와 회전축 기준

권장 방향:

```text
초기 무기는 작은 루프 터렛 중심으로 제한한다.
무기는 차량보다 먼저 읽히면 안 된다.
```

---

### 5.11 재질 기준

차량과 부품에 사용할 재질 범위를 정해야 한다.

결정해야 할 것:

- 차체 도장 금속
- 무광 장갑판
- 고무 타이어
- 유리/강화유리
- 플라스틱 몰딩
- 발광 부품
- 오염/마모 표현 방식

권장 방향:

```text
머티리얼 수를 적게 유지하고, 색상과 거칠기 차이로 충분히 구분한다.
```

---

### 5.12 색상 팔레트

게임 전체가 한 방향으로 보이도록 기본 색상 규칙을 정해야 한다.

결정해야 할 것:

- 기본 차량 색상 범위
- 장갑판 색상 범위
- 발광 색상 제한
- 경고 마킹 색상
- 진영/등급 색상 여부

권장 방향:

```text
저채도 기본색 + 제한적인 포인트 컬러를 사용한다.
```

---

### 5.13 손상/마모 표현 기준

차량이 얼마나 낡고 더러워 보일지 정해야 한다.

결정해야 할 것:

- 새 차 느낌과 폐차 느낌 사이의 위치
- 스크래치 강도
- 먼지/진흙/그을음 표현 강도
- 전투 손상 표현 여부
- 파손 메쉬를 따로 만들지 텍스처로 처리할지

권장 방향:

```text
초기에는 파손 메쉬보다 텍스처 기반 마모 표현을 우선한다.
```

---

### 5.14 원화 시트 포맷

모델링에 사용할 원화 시트 형식을 정해야 한다.

결정해야 할 것:

- 필요한 뷰 방향
- 배경 형식
- 정사영 여부
- 치수 기준선 여부
- 파츠 분리 표시 방식
- 색상/재질 콜아웃 방식

권장 기본 시트:

| 뷰 | 필요 여부 |
|---|---|
| Side View | 필수 |
| Front View | 필수 |
| Rear View | 필수 |
| Top View | 필수 |
| 3/4 View | 선택 |
| Detail Callout | 선택 |

중요 기준:

```text
3D 모델링용 원화는 멋진 일러스트보다 정사영 구조와 형태 가독성이 중요하다.
```

### 5.15 AI 이미지 생성 프롬프트 규칙

AI 원화 생성을 사용할 경우 프롬프트 규칙을 정해야 한다.

결정해야 할 것:

- 반드시 포함할 키워드
- 금지할 키워드
- 뷰 방향별 프롬프트 형식
- 배경/조명/렌더 스타일 기준
- 실제 브랜드 회피 문구
- 과도한 디테일 방지 문구

현재 기본 키워드 후보:

```text
simplified near-future civilian combat car,
clean readable silhouette,
low modeling complexity,
large simple armor panels,
no real car brand,
no excessive realistic detail,
orthographic concept sheet,
plain background
```

앞으로 생성할 원화 기준 문서는 다음 형식을 따른다.

# 문서 제목

## 8. 원화 결정 승인 기준

어떤 원화 기준이든 최종 결정하기 전에 아래 체크를 통과해야 한다.

| 체크 항목 | 통과 기준 |
|---|---|
| 1인 개발 적합성 | 혼자 만들거나 관리할 수 있어야 함 |
| 수정 가능성 | 모델링 초보자도 크기/위치/파츠 조정이 가능해야 함 |
| 실루엣 가독성 | 멀리서도 차급과 주요 장착부가 읽혀야 함 |
| 디테일 절제 | 작은 디테일이 과하게 메쉬화되지 않아야 함 |
| 에셋 재사용성 | 반복 사용 가능한 파츠가 있어야 함 |
| 언리얼 적용성 | 콜리전, 머티리얼, LOD, 피벗 처리가 가능해야 함 |
| 브랜드 회피 | 실제 차량 브랜드나 특정 모델 복제가 아니어야 함 |
| 게임성 연결 | 전투 시스템 또는 차량 역할과 연결되어야 함 |

최종 판단 문장:

```text
이 디자인 기준은 멋있는가보다, 혼자 끝까지 만들 수 있는가를 먼저 통과해야 한다.
```

## 10. Migration

### v0.4 적용 시 기존 작업 영향

- 이후 차급별 원화 프롬프트와 AI 모델링 검수는 `15_LoadoutBalance.md`의 장비 허용 기준을 함께 확인한다.
- 기존 차급 문서는 유지하며, 장착 가능 장비 판단만 `15_LoadoutBalance.md`를 참조한다.
- 이 변경은 기존 하드포인트 구현 구조를 바꾸지 않는다.

### v0.3 적용 시 기존 작업 영향

- 앞으로 예정/작성 문서의 제작성 기준은 AI 모델링 도구가 해석하기 쉬운 형태인지까지 포함한다.
- 기존 `초보자가 수정 가능한 형태` 표현은 AI 생성 결과를 초보자가 검수·후처리할 수 있는 형태로 해석한다.
- 복잡한 AI 모델링 결과는 장시간 수작업 수정 대상이 아니라 재생성 또는 교체 대상으로 본다.

### v0.2 적용 시 기존 작업 영향

- 이후 원화 기준 문서는 리소스별 다단계 제작을 전제로 하지 않는다.
- 각 결정 항목은 한 번의 생성/제작으로 C1 최종 후보에 가까워지도록 제약을 선명하게 작성한다.
- 기존 C0/C1/C2 표현은 제작 순서가 아니라 검수 기준으로 해석한다.

### v0.1 적용 시 기존 작업 영향

- `00_ArtDirection.md` v0.2의 기준을 변경하지 않는다.
- 이 문서는 `00_ArtDirection.md`의 하위 결정 체크리스트 역할을 한다.
- 기존 예정 문서 목록은 이 문서의 `6. 결정 문서 작성 순서`를 기준으로 더 세분화한다.
- 앞으로 원화 기준 문서를 만들 때는 이 문서의 순서를 우선한다.
- 이미 생성된 AI 차량 이미지가 있다면, 이 문서의 `8. 원화 결정 승인 기준`으로 재검토한다.
