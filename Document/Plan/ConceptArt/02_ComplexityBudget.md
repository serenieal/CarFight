# CarFight Concept Art - Complexity Budget

문서 버전: v0.3  
작성일: 2026-07-06  
문서 위치: `Document/Plan/ConceptArt/02_ComplexityBudget.md`  
상위 기준 문서: `Document/Plan/ConceptArt/00_ArtDirection.md`  
관련 문서: `Document/Plan/ConceptArt/01_DecisionChecklist.md`  
관련 범위: 차량 원화 제작 난이도, 디테일 예산, 파츠 수 제한, 모델링 수정 가능성 기준

---

## 1. 문서 목적

이 문서는 CarFight의 차량/부품/무기 원화를 그릴 때 허용할 **제작 난이도와 디테일 양**을 정의한다.

CarFight는 1인 개발 프로젝트이며, 개발자는 모델링 전문 지식이 거의 없는 상태를 전제로 한다.  
따라서 원화는 보기에는 그럴듯하지만 실제 제작과 수정이 어려운 복잡한 형태를 피해야 한다.

이 문서의 목적은 다음과 같다.

- 차량 1대당 허용할 파츠 수를 제한한다.
- 메쉬로 만들 디테일과 텍스처/머티리얼로 처리할 디테일을 구분한다.
- 너무 복잡한 원화가 생성되지 않도록 금지선을 정한다.
- AI 이미지 생성 결과를 검수할 기준을 만든다.
- AI 모델링 도구로 생성한 3D 후보를 검수·수정할 수 있는 구조를 유지한다.

---

## 2. 최상위 기준

이 문서의 최상위 기준은 다음과 같다.

```text
CarFight의 원화는 혼자 만들고, 혼자 수정하고, 혼자 관리할 수 있는 형태여야 한다.
```

따라서 원화에서 허용하는 디테일은 다음 우선순위를 따른다.

```text
제작 가능성 → 수정 가능성 → 게임 가독성 → 분위기 → 장식성
```

멋있는 디자인이라도 다음 조건에 해당하면 기본안에서 제외한다.

- 초보자가 모델링 수정하기 어렵다.
- 작은 파츠가 너무 많다.
- 곡면이 복잡하다.
- 실제 차량처럼 패널 라인이 과하다.
- 장갑 구조가 너무 세분화되어 있다.
- 텍스처로 처리할 수 있는 정보를 메쉬로 많이 만들고 있다.

## 3. 단일 패스 적용 기준

현재 CarFight는 시간 제약 때문에 리소스 하나를 여러 제작 단계로 나눠 완성하기 어렵다.

따라서 이 문서의 C0/C1/C2는 다음처럼 해석한다.

```text
C0/C1/C2는 제작 순서가 아니라 복잡도와 검수 등급이다.
```

기본 차량 리소스는 `C0 → C1 → C2` 순서로 제작하지 않는다.  
처음부터 **C1 Simple Game Asset 최종 후보**를 목표로 만든다.

| 항목 | 기준 |
|---|---|
| 기본 제작 목표 | C1 최종 후보 |
| C0 역할 | 실제 제작 전 머릿속/문서/원화 검수용 단순 판정 기준 |
| C1 역할 | 실제 게임에 넣을 기본 최종 후보 기준 |
| C2 역할 | 제한된 대표 차량용 확장 기준 |
| 실패한 결과물 처리 | 오래 붙잡고 수정하기보다 단순 기준으로 재생성/교체 우선 |

### 3.1 AI 모델링 적용 기준

이 문서의 복잡도 예산은 수작업 모델링 시간만 줄이기 위한 기준이 아니다.  
AI 모델링 결과가 엉키지 않게 만드는 입력 제한이기도 하다.

AI 모델링에서는 아래 문제가 생기기 쉽다고 보고 기준을 잡는다.

| 문제 | 문서 기준에서의 대응 |
|---|---|
| 파츠가 서로 붙어 구분되지 않음 | 큰 파츠 이름과 위치를 원화/프롬프트에서 명확히 지정 |
| 작은 디테일이 기하 구조로 과생성됨 | 작은 볼트/패널선/스크래치는 텍스처/노멀 대상으로 명시 |
| 실제 차량처럼 복잡한 패널이 생성됨 | `low modeling complexity`, `large simple shapes` 기준 유지 |
| 장갑판이 수십 개로 쪼개짐 | 큰 판형 장갑과 개수 제한 유지 |
| 언리얼 적용 시 피벗/콜리전이 애매함 | 휠, 차체, 루프 마운트처럼 중심축이 필요한 파츠를 단순화 |

판정 문장:

```text
AI 모델링 결과가 사람이 직접 정리하기 어려울 정도로 복잡하면 C1 후보가 아니다.
```

## 4. 복잡도 등급 정의

CarFight 원화는 아래 3단계 복잡도 등급으로 관리한다.

| 등급 | 이름 | 사용 시점 | 설명 |
|---|---|---|---|
| C0 | Blockout | 초기 형태 검증 | 차급 실루엣과 큰 덩어리만 확인 |
| C1 | Simple Game Asset | P0/P1 기본 제작 기준 | 실제 게임에 넣을 수 있는 단순 메쉬 기준 |
| C2 | Hero Detail | 제한적 고품질 기준 | 대표 차량이나 홍보 이미지용으로만 제한 사용 |

CarFight의 기본 차량 원화 기준은 **C1 Simple Game Asset**이다.

```text
기본 기준: C1 Simple Game Asset
```

C2는 기본 기준이 아니다.  
C2는 나중에 대표 차량 1~2대를 고품질로 만들 필요가 있을 때만 사용한다.

---

## 4. 복잡도 등급별 허용 범위

### 4.1 C0 - Blockout

C0는 형태 검증용이다.

목적:

- 차급 실루엣 확인
- 휠 위치 확인
- 루프 마운트 위치 확인
- 차량 길이/폭/높이 비례 확인
- 카메라 거리에서 읽히는지 확인

허용 요소:

| 요소 | 기준 |
|---|---|
| 차체 | 큰 박스/쐐기 형태 |
| 휠 | 원통 4개 |
| 창문 | 단순 검은 면 |
| 장갑 | 큰 판 2~4개 |
| 무기 마운트 | 단순 원통/박스 |
| 작은 디테일 | 없음 |

C0에서는 멋을 보지 않는다.  
오직 **차급과 큰 비례가 읽히는지**만 본다.

---

### 4.2 C1 - Simple Game Asset

C1은 CarFight의 기본 제작 기준이다.

목적:

- 실제 게임 리소스로 사용할 수 있는 수준
- 1인 개발자가 수정 가능한 수준
- AI 모델링 도구가 생성하기 쉽고 초보자가 후처리 가능한 수준
- 차량 종류를 여러 대 만들 수 있는 수준

허용 요소:

| 요소 | 기준 |
|---|---|
| 차체 | 단순화된 민간 차량 실루엣 |
| 휠 | 4개 분리 파츠 |
| 창문 | 단순 면 또는 단순 유리 파츠 |
| 장갑 | 큰 판형 패널 중심 |
| 범퍼 | 단순 보강대 허용 |
| 휠가드 | 단순 형태만 허용 |
| 센서 | 큰 박스형/렌즈형 중심 |
| 하드포인트 | 루프 중앙 우선 |
| 작은 디테일 | 대부분 텍스처/머티리얼 처리 |

C1의 핵심은 다음이다.

```text
큰 형태는 메쉬로 만들고, 작은 정보는 텍스처로 처리한다.
```

---

### 4.3 C2 - Hero Detail

C2는 제한적으로만 사용한다.

목적:

- 대표 차량
- 타이틀 이미지
- 스팀 페이지 이미지
- 시연용 하이라이트 차량

허용 요소:

| 요소 | 기준 |
|---|---|
| 차체 | C1보다 조금 더 많은 면 분할 허용 |
| 장갑 | 중간 크기 패널 추가 허용 |
| 센서 | 추가 디테일 허용 |
| 표면 마모 | 텍스처 중심으로 강화 |
| 작은 파츠 | 제한적으로만 허용 |

C2는 다음 조건을 지켜야 한다.

```text
C2라도 실제 차량처럼 복잡한 패널 라인과 수많은 작은 부품은 금지한다.
```

## 5. 차량 1대당 권장 파츠 예산

아래 기준은 C1 Simple Game Asset 기준이다.

### 5.1 필수 파츠

| 파츠 | 권장 개수 | 설명 |
|---|---:|---|
| Body_Main | 1 | 차체 기본 덩어리 |
| Wheel_FL | 1 | 앞 왼쪽 휠 |
| Wheel_FR | 1 | 앞 오른쪽 휠 |
| Wheel_RL | 1 | 뒤 왼쪽 휠 |
| Wheel_RR | 1 | 뒤 오른쪽 휠 |
| Glass_Main | 1~3 | 창문을 통합하거나 전/측/후로 단순 분리 |
| Mount_Roof | 0~1 | 루프 터렛 마운트 |

권장 필수 파츠 수:

```text
기본 5~8개
```

---

### 5.2 선택 파츠

| 파츠 | 권장 개수 | 설명 |
|---|---:|---|
| Armor_Front | 0~1 | 전면 장갑판 |
| Armor_Left | 0~1 | 좌측 장갑판 |
| Armor_Right | 0~1 | 우측 장갑판 |
| Armor_Rear | 0~1 | 후면 장갑판 |
| Bumper_Front | 0~1 | 전면 보강 범퍼 |
| Bumper_Rear | 0~1 | 후면 보강 범퍼 |
| WheelGuard_Front | 0~2 | 앞 휠가드 |
| WheelGuard_Rear | 0~2 | 뒤 휠가드 |
| Sensor_Box | 0~2 | 센서/카메라 박스 |
| Cooling_Box | 0~1 | 냉각/전자장비 박스 |

권장 선택 파츠 수:

```text
기본 4~10개
```

---

### 5.3 총 파츠 예산

C1 차량 1대의 권장 총 파츠 수는 다음과 같다.

| 기준 | 파츠 수 |
|---|---:|
| 최소 작동 차량 | 5~8개 |
| 기본 전투 차량 | 10~16개 |
| 상한 권장치 | 20개 이하 |
| 초과 주의 | 21개 이상 |
| 기본 금지 | 30개 이상 |

CarFight의 기본 차량 1대는 다음 범위를 목표로 한다.

```text
10~16개 파츠
```

20개를 넘기면 원화를 다시 검토한다.  
30개를 넘기면 기본 제작 기준에서 제외한다.

## 6. 메쉬 디테일 예산

### 6.1 메쉬로 만들어야 하는 디테일

다음 요소는 게임플레이나 실루엣에 영향을 주므로 메쉬로 만든다.

| 요소 | 이유 |
|---|---|
| 차체 큰 덩어리 | 차량 차급을 결정함 |
| 휠 | 회전/조향 시각 동기화 필요 |
| 루프 마운트 | 무기 장착 기준점이 됨 |
| 큰 장갑판 | 전투 개조 실루엣을 만듦 |
| 큰 범퍼 보강대 | 전면/후면 인상을 만듦 |
| 큰 휠가드 | 측면 실루엣에 영향 |
| 큰 센서 박스 | 근미래 기능 인상을 만듦 |
| 큰 냉각구/흡기구 | 기능적 설득력을 줌 |

---

### 6.2 상황에 따라 메쉬로 만들 디테일

다음 요소는 크기와 카메라 가독성에 따라 결정한다.

| 요소 | 기준 |
|---|---|
| 중간 크기 볼트 | 가까이서 자주 보이면 메쉬, 아니면 텍스처 |
| 두꺼운 패널 라인 | 실루엣에 보이면 메쉬, 아니면 텍스처 |
| 손잡이 | 게임에서 중요하지 않으면 텍스처 |
| 사이드미러 | 차량 인상에 중요하면 단순 메쉬 |
| 라이트 하우징 | 큰 형태만 메쉬, 내부 디테일은 머티리얼 |
| 배기구 | 큰 형태만 메쉬 |

---

### 6.3 텍스처/머티리얼로 처리할 디테일

다음 요소는 기본적으로 메쉬로 만들지 않는다.

| 요소 | 권장 처리 |
|---|---|
| 작은 볼트 | 텍스처/노멀 |
| 얇은 패널 라인 | 텍스처/노멀 |
| 작은 스크래치 | 텍스처 |
| 페인트 벗겨짐 | 텍스처 |
| 먼지/진흙 | 텍스처/머티리얼 |
| 작은 경고 라벨 | 텍스처 |
| 정비용 숫자 | 텍스처 |
| 얇은 케이블 | 기본 제외 또는 텍스처 |
| 작은 그릴 구멍 | 텍스처/마스크 |
| 미세한 용접 자국 | 텍스처/노멀 |

## 7. 금지 디테일 기준

아래 요소는 초기 C1 기준에서 금지한다.

| 금지 요소 | 이유 |
|---|---|
| 실제 차량 하부 구조 재현 | 모델링 난이도 대비 게임 효과가 낮음 |
| 복잡한 서스펜션 노출 | 수정 난이도와 애니메이션 부담이 큼 |
| 엔진룸 내부 디테일 | 게임플레이에 필요하지 않음 |
| 열리는 문/보닛 전제 내부 구조 | 기능 구현 범위가 커짐 |
| 수십 개의 작은 장갑 조각 | UV/머티리얼/수정 비용 증가 |
| 얇은 안테나 다발 | 파손/LOD/가독성 문제 |
| 복잡한 케이블 묶음 | 모델링과 정리 난이도 높음 |
| 브랜드 고유 디테일 | 실제 차량 복제 위험 |
| 지나치게 복잡한 곡면 | 초보 수정이 어려움 |
| 과한 비대칭 디테일 | 좌우 재사용과 수정이 어려움 |

---

## 8. 곡면 복잡도 기준

CarFight 차량은 실제 자동차처럼 정교한 곡면을 많이 쓰지 않는다.

권장 방향:

```text
큰 곡면은 허용하되, 작은 굴곡이 반복되는 복잡한 표면은 피한다.
```

| 곡면 유형 | 허용 여부 | 설명 |
|---|---|---|
| 큰 차체 곡면 | 허용 | 보닛, 루프, 펜더의 큰 흐름 |
| 단순한 베벨 | 허용 | 하드서피스 느낌을 주는 정도 |
| 복잡한 자동차 패널 굴곡 | 제한 | 실제 차량 복제 느낌과 제작 난이도 증가 |
| 얇은 주름형 굴곡 | 금지 | 노멀/텍스처 처리 권장 |
| 복잡한 유선형 슈퍼카 곡면 | 기본 금지 | CarFight 기본 방향과 제작성에 맞지 않음 |

---

## 9. 좌우 대칭 기준

1인 개발에서는 좌우 대칭 구조가 중요하다.

권장 기준:

| 항목 | 기준 |
|---|---|
| 기본 차체 | 좌우 대칭 |
| 휠/휠가드 | 좌우 대칭 |
| 측면 장갑 | 좌우 대칭 우선 |
| 센서 | 비대칭 가능하지만 1~2개만 |
| 손상/마모 | 텍스처에서 비대칭 처리 가능 |
| 하드포인트 | 초기에는 중앙 또는 좌우 대칭 우선 |

비대칭은 차량 개성을 주는 데 좋지만, 초기에는 많이 쓰지 않는다.

```text
형태 비대칭은 줄이고, 색상/마킹/마모에서 비대칭을 준다.
```

## 10. 재사용 가능한 디테일 기준

CarFight는 차량을 여러 대 만들어야 하므로, 반복 사용 가능한 파츠를 우선한다.

우선 재사용 후보:

- 휠
- 타이어
- 루프 터렛 마운트
- 단순 장갑판
- 센서 박스
- 작은 카메라 렌즈
- 범퍼 보강대
- 휠가드
- 냉각 박스
- 라이트 모듈

재사용 파츠 기준:

| 기준 | 설명 |
|---|---|
| 형태가 단순해야 함 | 여러 차급에 붙이기 쉬워야 함 |
| 크기 조정이 쉬워야 함 | 스케일 조정으로 재사용 가능해야 함 |
| 방향성이 명확해야 함 | Forward/Up 기준이 헷갈리지 않아야 함 |
| 피벗이 예측 가능해야 함 | 배치와 회전이 쉬워야 함 |
| 머티리얼 슬롯이 적어야 함 | 관리 부담을 줄이기 위함 |

## 11. 원화 검수 기준

AI 이미지나 수작업 원화를 검수할 때 아래 질문을 사용한다.

### 11.1 통과 질문

아래 질문에 대부분 `예`라고 답할 수 있어야 한다.

- 차급 실루엣이 바로 읽히는가?
- 파츠 수가 20개 이하로 정리될 수 있는가?
- 큰 형태가 단순한가?
- 휠, 차체, 장갑, 마운트가 구분되는가?
- 작은 디테일을 텍스처로 넘길 수 있는가?
- 좌우 대칭을 활용할 수 있는가?
- 초보자가 파츠 위치나 크기를 수정할 수 있는가?
- 실제 브랜드 고유 형태를 피하고 있는가?

### 11.2 탈락 질문

아래 질문에 하나라도 강하게 `예`라면 재생성 또는 수정한다.

- 실제 차량처럼 패널 라인이 너무 많은가?
- 작은 돌출 부품이 과하게 많은가?
- 장갑판이 수십 개 조각으로 나뉘어 있는가?
- 차체가 너무 복잡한 곡면으로 이루어져 있는가?
- 무기가 차량보다 먼저 보이는가?
- 하부 구조나 엔진 구조가 복잡하게 노출되어 있는가?
- 특정 실제 차량 모델처럼 보이는가?
- 내가 직접 고치기 어려울 정도로 복잡한가?

## 12. AI 프롬프트 반영 기준

AI 이미지 생성 프롬프트에는 복잡도 제한 문구를 반드시 넣는다.

### 12.1 권장 포함 문구

```text
simplified design,
low modeling complexity,
clean readable silhouette,
large simple shapes,
large simple armor panels,
minimal small details,
game asset concept,
easy to model,
easy to modify,
orthographic view,
plain background
```

### 12.2 권장 금지 문구

```text
no excessive realistic detail,
no complex panel lines,
no tiny mechanical parts,
no exposed suspension,
no exposed engine,
no real car brand,
no real car copy,
no overly complex surface,
no excessive greebles,
no many small armor plates
```

### 12.3 기본 프롬프트 조각

```text
simplified near-future civilian combat car,
low modeling complexity,
clean readable silhouette,
large simple armor panels,
minimal small details,
easy to model game asset concept,
no real car brand,
no excessive realistic detail,
orthographic view,
plain background
```

## 13. C1 차량 원화 기본 판정표

원화 1장을 보고 아래 기준으로 판정한다.

| 항목 | 통과 기준 |
|---|---|
| 차급 실루엣 | 3초 안에 대략적인 차급이 읽힘 |
| 파츠 수 | 10~16개 권장, 20개 이하 유지 |
| 장갑판 | 큰 판형 위주, 작은 조각 남발 금지 |
| 곡면 | 큰 곡면만 허용, 복잡한 세부 굴곡 금지 |
| 무기/마운트 | 차량보다 과하게 크지 않음 |
| 디테일 | 작은 정보는 텍스처로 넘길 수 있음 |
| 수정성 | 초보자가 위치/크기/색상을 수정 가능 |
| 브랜드 회피 | 특정 실제 모델 복제로 보이지 않음 |

최종 판정:

```text
C1 기준을 통과하지 못하면 기본 차량 리소스 후보로 쓰지 않는다.
```

## 17. Migration

### v0.3 적용 시 기존 작업 영향

- 기존 파츠 수, 디테일 예산, 금지 디테일 기준은 AI 모델링 입력 제한으로도 사용한다.
- AI 모델링 결과가 파츠 수 20개 이하로 정리되지 않거나 작은 디테일이 기하 구조로 과생성되면 재생성한다.
- `초보자가 수정 가능`은 생성된 모델의 파츠 위치, 크기, 머티리얼, 피벗을 혼자 정리할 수 있다는 뜻으로 해석한다.

### v0.2 적용 시 기존 작업 영향

- 기존 C0/C1/C2 기준은 리소스별 순차 제작 단계가 아니라 복잡도 검수 기준으로 해석한다.
- 앞으로 차량 원화는 처음부터 C1 Simple Game Asset 최종 후보를 목표로 검수한다.
- C0 수준의 블록아웃은 별도 리소스 제작 단계가 아니라 머릿속/문서/프롬프트 검수용으로만 사용한다.
- 결과물이 C1 기준을 크게 벗어나면 긴 수정 작업보다 재생성 또는 교체를 우선한다.

### v0.1 적용 시 기존 작업 영향

- 기존 `00_ArtDirection.md`의 단순화 원칙을 수치화한 하위 기준으로 사용한다.
- 기존 `01_DecisionChecklist.md`의 `제작 난이도 등급` 항목은 이 문서의 C0/C1/C2 기준을 따른다.
- 앞으로 생성되는 차량 원화는 기본적으로 C1 Simple Game Asset 기준으로 검수한다.
- 이미 생성된 차량 이미지가 있다면 다음 기준으로 재검토한다.
  - 파츠 수가 20개 이하로 정리될 수 있는가?
  - 작은 디테일을 텍스처로 넘길 수 있는가?
  - 복잡한 패널 라인이나 실제 차량 디테일이 과하지 않은가?
  - 초보자가 직접 수정 가능한 구조인가?
