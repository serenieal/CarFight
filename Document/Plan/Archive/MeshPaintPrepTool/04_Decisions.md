# MeshPaintPrepTool - Decisions

> 역할: `MeshPaintPrepTool` 작업 중 확정된 결정과 사용자 확인이 필요한 미결 사항을 관리한다.
> 문서 버전: v0.4
> 마지막 정리(Asia/Seoul): 2026-06-30
> 상태: Draft / Decision Log

---

## 1. 확정 결정

| ID | 결정 | 이유 | 영향 |
|---|---|---|---|
| D001 | 대상은 자동차가 아니라 범용 `Static Mesh`다. | 터렛, 총알, 임시 프롭도 같은 문제가 생긴다. | 플러그인 이름과 에셋 이름에서 Vehicle / Car를 제외한다. |
| D002 | 플러그인 이름은 `MeshPaintPrepTool`로 둔다. | 기능이 명확하고 범용성이 있다. | 저장소 / 플러그인 / 문서 폴더 이름 기준이 된다. |
| D003 | 별도 Git 저장소로 관리한다. | 다른 프로젝트에서도 재사용해야 한다. | CarFight는 소비자 프로젝트가 된다. |
| D004 | CarFight에서는 서브모듈로 관리한다. | 원본 코드와 프로젝트 검증을 분리한다. | 경로는 `UE/Plugins/MeshPaintPrepTool`이다. |
| D005 | Editor-only 플러그인으로 시작한다. | 런타임 기능이 필요하지 않다. | Runtime 모듈은 만들지 않는다. |
| D006 | v1.0부터 Auto UV 옵션을 포함한다. | 에디터 제작 메시에는 UV가 없을 가능성이 높다. | UV 검사와 Auto UV 실패 처리 필요. |
| D007 | 기본 UV 채널은 `UV0`이다. | 기본 머티리얼 샘플링과 Mesh Paint 결과가 맞기 쉽다. | UV1 지원은 후속으로 미룬다. |
| D008 | 생성 에셋은 메시 폴더 아래 `Paint` 폴더에 만든다. | 메시와 페인트 자산을 가까운 곳에 보관한다. | 프로젝트별 경로 하드코딩을 피한다. |
| D009 | v1.0은 단일 Static Mesh 처리로 제한한다. | 안정적인 첫 버전이 중요하다. | 일괄 처리는 후속 기능이다. |
| D010 | 데칼은 범위에서 제외한다. | 총알자국 같은 별도 용도다. | 이 도구는 텍스처 페인트 준비에 집중한다. |
| D011 | 원격 저장소 URL은 `https://github.com/serenieal/MeshPaintPrepTool`이다. | 플러그인 이름 기준으로 새 저장소를 만들었다. | 서브모듈 URL 기준이 된다. |
| D012 | 저장소 공개 범위는 비공개다. | 개인 사용이 우선이다. | 외부 배포 문서는 후순위다. |
| D013 | 라이선스 파일은 현재 만들지 않는다. | 개인 사용 전제다. | README에는 라이선스 미지정 상태를 명시한다. |
| D014 | 기본 텍스처 해상도는 1024다. | 일반 임시 메시에 무난한 기본값이다. | UI 기본값으로 사용한다. |
| D015 | 작은 메시용으로 256 / 512 해상도를 선택할 수 있게 한다. | 총알 같은 작은 메시에는 1024가 과할 수 있다. | 해상도 프리셋이 필요하다. |
| D016 | 기본 브랜치는 `main`이다. | GitHub 원격 저장소 초기 push 기준이다. | 서브모듈은 `main`의 커밋을 추적한다. |
| D017 | CarFight에서 플러그인을 활성화한다. | 서브모듈 추가 후 빌드 검증을 위해 필요하다. | `UE/CarFight_Re.uproject`에 `MeshPaintPrepTool` 항목을 추가한다. |
| D018 | v0.4 Auto UV는 박스 기반 UV0 생성으로 구현한다. | Static Mesh Editor API가 안정적이고 에디터 제작 임시 메시의 1차 페인트 준비에 충분하다. | XAtlas / Patch 기반 고급 Auto UV는 후속으로 분리한다. |

## 2. 이름 정책

차량 전용 이름은 사용하지 않는다.

| 금지 방향 | 권장 방향 |
|---|---|
| `CarPaint` | `MeshPaint` |
| `VehicleSkin` | `PaintableMesh` |
| `SedanSkin` | `{MeshName}_Paint` |
| `VehiclePaintPrep` | `MeshPaintPrepTool` |

권장 에셋 이름:

| 종류 | 이름 |
|---|---|
| 플러그인 | `MeshPaintPrepTool` |
| 부모 머티리얼 | `M_PaintableMesh` |
| 텍스처 | `T_{MeshName}_Paint` |
| 머티리얼 인스턴스 | `MI_{MeshName}_Paint` |

## 3. 결정 상태

아래는 구현 전에 확인한 결정 상태다.

| ID | 질문 | 현재 상태 |
|---|---|---|
| Q001 | 별도 Git 원격 저장소 URL을 무엇으로 할까? | 확정: `https://github.com/serenieal/MeshPaintPrepTool` |
| Q002 | 저장소를 공개로 할까, 비공개로 할까? | 확정: 비공개 |
| Q003 | 라이선스를 무엇으로 할까? | 확정: 현재 만들지 않음 |
| Q004 | 기본 텍스처 해상도를 1024로 둘까? | 확정: 기본 1024, 더 작은 해상도 선택 가능 |
| Q005 | 플러그인 UI 표시 이름을 영문으로 둘까, 한글 병기할까? | 확정: `Mesh Paint Prep` |
| Q006 | Auto UV 실패 시 Modeling Mode 수동 안내만 할까, 실패 메시지에 상세 진단을 넣을까? | v1.0은 간단 안내 추천 |

## 4. 보류 결정

아래 항목은 v1.0 이후로 보류한다.

| ID | 항목 | 보류 이유 |
|---|---|---|
| H001 | UV1 / UV2 선택 지원 | 머티리얼 Texture Coordinate 정책까지 함께 필요 |
| H002 | 여러 메시 일괄 처리 | 단일 메시 안정화 후 확장 |
| H003 | UV 겹침 시각화 | 구현 범위가 커짐 |
| H004 | 데칼 생성 도구 통합 | 용도가 다름 |
| H005 | 런타임 페인트 저장 | Editor-only 플러그인 목표와 다름 |
| H006 | Marketplace 패키징 | 내부 사용 안정화 후 판단 |
| H007 | XAtlas / Patch 기반 고급 Auto UV | 빌드 안정성과 단일 메시 기본 흐름 검증을 먼저 완료해야 함 |

## 5. 결정 변경 규칙

결정을 바꿀 때는 아래를 지킨다.

1. 조용히 덮어쓰지 않는다.
2. 변경 이유를 Changelog에 남긴다.
3. 기존 결정 ID는 삭제하지 않고 `Superseded`로 표시한다.
4. 구현이 이미 시작된 결정은 마이그레이션 지침을 함께 작성한다.

## 6. Changelog

### v0.4

- v0.4 Auto UV 구현 방식을 박스 기반 UV0 생성으로 확정했다.
- 고급 XAtlas / Patch 기반 Auto UV를 보류 결정으로 추가했다.

### v0.3

- 기본 브랜치 `main`과 CarFight 프로젝트 내 플러그인 활성화 결정을 추가했다.
- 초기 커밋과 서브모듈 연결이 완료된 상태를 반영했다.

### v0.2

- 원격 저장소 URL, 비공개 여부, 라이선스 없음, UI 표시 이름을 확정 결정으로 반영했다.
- 텍스처 해상도 정책을 기본 1024와 작은 메시용 256 / 512 선택 가능으로 확정했다.

### v0.1

- 범용 Static Mesh 도구, 별도 Git 저장소, CarFight 서브모듈 방식을 확정 결정으로 기록했다.
- 차량 전용 명명 금지와 범용 이름 정책을 기록했다.
- 구현 전 사용자 확인이 필요한 항목을 `Q001`부터 `Q006`까지 분리했다.

## 7. Migration 메모

- 기존 문서나 에셋에 `VehiclePaintPrep` 같은 차량 전용 이름을 사용한 흔적이 생기면 `MeshPaintPrepTool` 기준으로 정리한다.
- 이미 만든 CarFight 테스트 에셋은 플러그인 설계 결정의 근거로만 사용하고, 플러그인 코드에는 직접 참조하지 않는다.
