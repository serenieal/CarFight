## 4. 현재 확정된 방향

현재 확정된 최상위 방향은 다음과 같다.

> CarFight는 차량을 직접 몰고 조준하며 싸우되, 승패는 피팅·거리·각도·속도·락온·배터리/연료·탄약 중량 운용에서 갈리는 전략형 차량 전투 게임이다.

추가 원칙:

- 현재 `CombatPlan`의 P0 / P1 기준은 싱글플레이 AI 교전이다.
- 멀티플레이, 팀전, 서버 / 네트워크 전제는 현재 `CombatPlan` 범위에서 제외한다.
- 열은 차량 전체 자원이 아니라 무기별 자원이다.
- 탄종과 탄수는 피팅의 핵심이며 차량 중량과 연결한다.
- 자동차의 정체성은 접지, 선회, 제동, 충돌, 지형, 장갑 방향에서 드러나야 한다.
- 고정 무기가 아닌 모든 무기에는 각속도 개념이 존재한다.
- 강한 한 방 무기는 강해야 하지만, 빠르게 붙거나 측면을 파고드는 상대를 쉽게 따라잡지는 못해야 한다.
- 발사, Impact와 파괴 결과는 플레이어가 즉시 이해할 수 있도록 화면 UI와 시각 FX가 판정 결과에 1:1로 대응해야 한다.
- CarFight는 게임 사운드를 지원하지 않으며 청각 피드백을 전투 완성 조건이나 장기 확장 후보로 요구하지 않는다.

### 4.1 현재 P0 전투 표현 연결

현재 실제 구현 순서와 상세 범위는 ProjectSSOT, Systems와 대표 Plan이 소유한다.

```text
현재 전역 Active: 없음
최근 완료: CF-FQ-024 전투 FX / Done / User PIE PASS
현재 구현: Document/Systems/Combat/CombatFx.md
완료 Plan: Document/Plan/CombatFxAudio/ImplementationDesign.md
검증 ID: CF-TC-021 PASS / Visual FX Only
다음 Candidate: CF-FQ-019 주행·전투 반복 테스트
일시중지: CF-FQ-026 타겟 선택 시스템 / TS-P0-08
```

승인된 발사, 첫 Impact와 최초 차량 파괴가 Niagara FX로 정확히 1회씩 읽히는 P0 기준은 완료됐다.
`CombatFxAudio`는 레거시 디렉터리명이며 SoundWave, MetaSound, AudioComponent, 차량 오디오와 믹싱은 프로젝트 전역 비지원 범위다.

## 7. 현재 확정된 차량 기동 / 거리 / 각도 원칙

`04_Positioning.md`에서 확정한 핵심 원칙은 아래와 같다.

- 좋은 위치란 내 무기 효율은 높이고 상대 무기 효율은 낮추는 위치다.
- 거리 구간은 초근거리 / 근거리 / 중거리 / 장거리 / 초장거리로 나눈다.
- 정면은 가장 튼튼하고, 측면은 전술적 약점이며, 후면은 엔진/연료 계통이 있는 큰 약점이다.
- 고속은 생존과 위치 선점에 유리하지만 조준 안정성을 낮춘다.
- 저속/정지는 조준에 유리하지만 피격과 락온에 취약하다.
- 중요한 것은 절대 속도보다 상대 기준 횡방향 속도다.
- 빠른 차량은 상대 무기의 각속도 한계를 넘는 방식으로 생존한다.

## 8. 현재 확정된 조준 방식 원칙

`05_AimingSystem.md`에서 확정한 조준 방식은 아래 5개다.

1. 고정 무기
2. 짐벌 무기
3. 터렛 무기
4. 락온 무기
5. 수동 유도 무기

핵심 원칙:

- 플레이어 조준점과 무기 실제 조준점은 분리된다.
- 고정 무기는 강하지만 어렵다.
- 짐벌 무기는 편하지만 화력 효율이 낮다.
- 터렛은 자유롭지만 각속도와 안정화 제한을 가진다.
- 락온은 강한 압박이지만 대응 가능해야 한다.
- 수동 유도는 강하지만 조작 부담이 크므로 P1 이후로 둔다.
- 배터리는 총을 쏘기 위한 마나가 아니라, 조준 / 센서 / 방어장비를 보조하는 자동차 전장 전력이다.

## 11. 현재 확정된 방어 / 장갑 원칙

`08_DefenseArmor.md`에서 확정한 주 방어 구조는 아래 3층이다.

1. 쉴드
2. 장갑
3. 차량 내구도

부품 상태는 별도의 기능 상태 계층이다.

P0 장갑 타입:

1. 경량 장갑
2. 표준 장갑
3. 중장갑

P0 부품:

1. 바퀴
2. 엔진
3. 터렛

핵심 원칙:

- 쉴드가 흡수한 피해는 부품에 전달되지 않는다.
- 장갑 피해부터 제한적 또는 경미한 부품 피해가 가능하다.
- 차량 내구도 피해부터 본격적인 부품 손상이 가능하다.
- 정면은 강해야 하고 측면과 후면은 의미 있는 약점이어야 한다.
- 부품 손상은 차량 내구도를 모두 깎지 않아도 전투 흐름을 바꿀 수 있어야 한다.
- 장갑 강화는 반드시 중량과 기동성 손실을 동반해야 한다.

## 12. 현재 확정된 락온 / 센서 / 전자전 원칙

`09_LockSensorEW.md`에서 확정한 핵심 구조는 아래와 같다.

- 타겟 선택과 장비 락온은 별도 상태다.
- 별도 락온 입력을 필수로 두지 않으며 기본 방식은 선택 타겟 조준 영역 유지형이다.
- 무기와 장비별로 다른 락온 획득 방식을 지원한다.
- 레이더는 월드 Actor를 직접 검색하는 미니맵이 아니라 Sensor Contact를 표시한다.
- 가시 식별과 센서 스캔은 별도 정보 획득 경로다.
- 미공개 타겟 정보는 `???`로 유지한다.
- 락온은 자동 명중 시스템이 아니라 전투 압박 상태다.
- 락온은 센서 범위, 시야, 거리, 목표 움직임, 배터리 상태에 영향을 받는다.
- 빠른 차량은 락온 안정도를 흔드는 방식으로 생존할 수 있어야 한다.
- 엄폐, 연막, 플레어, 재밍은 락온에 대한 명확한 대응 수단이다.
- 대응 없는 락온은 금지한다.

P0 최소 구현:

1. Sensor Contact와 기본 레이더
2. 선택 대상과 장비 락온 상태 분리
3. 기본 조준 유지형 락온 게이지
4. 가시 식별과 센서 스캔 공개 상태
5. 배터리 소모
6. 엄폐로 락온 차단
7. 횡방향 속도에 따른 락온 시간 증가
8. 경량 락온 미사일
9. 연막 또는 플레어 1종

## 13. 현재 확정된 배터리 / 연료 / 탄약 자원 원칙

`10_BattFuel.md`에서 확정한 전투 자원과 비용은 아래처럼 분리한다.

1. 차량 배터리
2. 연료
3. 탄약
4. 무기 내부 충전
5. 무기별 열
6. 중량

핵심 원칙:

- 차량 배터리는 센서, 락온, 터렛 안정화, 방어장비, 전자전에 사용한다.
- 에너지 무기라는 이유만으로 차량 배터리를 자동 소비하지 않는다.
- Weapon Charge는 차량 배터리와 다른 무기별 자원일 수 있다.
- 연료는 주행, 고출력 주행, 추격, 이탈, 작전 지속력에 연결된다.
- 탄약과 탄수는 출격 전 피팅 선택이며 차량 성능과 연결된다.
- 무기별 열은 차량 전체 열이 아니라 무기별 사격 제한 자원이다.
- 중량은 차체, 장갑, 무기, 탄약, 연료, 배터리, 방어장비의 총합 비용이다.
- 각 자원은 게임플레이 규칙을 분리하고 UI 표현만 공통 채널로 통합할 수 있다.

P0 최소 구현:

- 배터리 게이지
- 연료량과 중량 반영
- 탄종 / 탄수 / 중량 반영
- 무기별 열 게이지
- 필요한 무기의 내부 충전 표시 계약
- 총중량에 따른 주행 성능 변화

4. 과열 시 해당 무기 사격 불가
5. UI에 무기별 열 상태 표시

## 15. 현재 확정된 하드포인트 / 무기 그룹 원칙

`12_Hardpoints.md`에서 확정한 핵심 원칙은 아래와 같다.

- 무기 그룹은 전투 중 자원과 사격 리듬을 관리하는 조작 단위다.

P0 하드포인트:

## 16. 현재 확정된 피팅 원칙

`13_Fitting.md`에서 확정한 핵심 원칙은 아래와 같다.

- 차량은 클래스가 아니라 플랫폼이다.
- 피팅은 전투 방식을 결정해야 한다.
- 중량은 피팅 선택의 핵심 비용이다.
- 탄약과 연료도 장착물처럼 중량을 가진다.
- 강한 장비는 화력뿐 아니라 중량, 각속도, 열, 배터리, 탄약 비용을 가져야 한다.
- P0에서는 중량 기반 피팅 감각부터 검증한다.

P0 피팅 범위:

- 차체 기본 중량
- 장갑 타입 선택
- 무기 4종 장착
- 탄종 / 탄수 선택
- 연료량 선택
- 단일 배터리 게이지
- 총중량 계산과 주행 성능 변화

## 17. 현재 확정된 전투 UI 원칙

`14_CombatUI.md`에서 확정한 핵심 원칙은 아래와 같다.

- 현재는 인게임 UI만 구현하되 전체 게임플로우 확장 가능한 LocalPlayer UI Root를 사용한다.
- 싱글플레이 Pause는 입력뿐 아니라 게임 시뮬레이션 전체를 멈춘다.
- 기본 시점은 외부 3인칭이며 운전석 시점은 사용하지 않는다.
- 포탑 시점은 후속 확장 가능성을 유지한다.
- 미니맵 대신 Sensor Contact 기반 전투 레이더를 사용한다.
- Shield / Armor / Vehicle Integrity와 부품 상태를 분리 표시한다.
- 선택 타겟 패널을 유지하고 미공개 필드는 `???`로 표시한다.
- 가시 식별과 센서 스캔 정보를 분리 표시한다.
- 탄약, 배터리, 충전과 열의 규칙은 분리하고 UI 채널만 공통화한다.
- 속도계는 숫자형이며 판독성 중심 전투 SF HUD를 사용한다.
- 프로젝트 전역 사운드 비지원 정책에 따라 모든 경고는 시각 정보만으로 이해 가능해야 한다.

P0 UI 범위:

- UI Root와 레이어
- 싱글플레이 완전 Pause Menu
- 플레이어 조준점과 무기 실제 조준점
- 숫자형 속도계
- Shield / Armor / Vehicle Integrity와 부품 손상
- 현재 무기의 공통 자원 채널
- 선택 타겟 패널과 `???`
- Radar Contact와 화면 밖 방향
- 기본 락온 게이지와 실패 원인
- 16:9 / 21:9 / 32:9 안전영역 검증

## 18. 현재 확정된 전투 AI 원칙

`15_CombatAI.md`에서 확정한 핵심 원칙은 아래와 같다.

- AI는 전투 시스템을 설명하는 역할을 해야 한다.
- AI 역할은 차량 피팅과 무기 타입에 의해 달라져야 한다.
- AI도 무기 각속도, 과열, 탄약, 락온, 모듈 손상 규칙을 따라야 한다.
- P0 AI는 똑똑함보다 패턴의 선명함이 중요하다.
- 각 AI는 플레이어에게 하나의 전투 교훈을 전달해야 한다.

P0 AI 역할:

1. 추격형 경량 차량
2. 중거리 오토캐논 차량
3. 중장갑 대구경 터렛 차량
4. 경량 락온 미사일 차량

## 19. 현재 확정된 P0 프로토타입 범위

`16_P0Prototype.md`에서 확정한 P0 목표는 아래와 같다.

> P0의 목표는 CarFight의 전투 정체성인 차량 기동 + 직접 조준 + 피팅/중량 + 무기 각속도 + 무기별 열 + 락온 대응이 실제로 재미있는지 확인하는 것이다.

P0 성공 기준:

- 좋은 위치를 만들면 유리하다고 느낀다.
- 빠른 차량이 느린 대구경 무기의 각속도 한계를 이용할 수 있다.
- 중장갑 차량은 정면으로 강하지만 측후면이 위험하다.
- 무기별 열 때문에 쏘고 쉬는 리듬이 생긴다.
- 탄약 / 장갑 / 연료 / 배터리 중량이 피팅 선택으로 체감된다.
- 락온은 위협적이지만 대응 가능하다.
- 모듈 손상으로 전투 흐름이 바뀐다.
