# MeshPaintPrepTool - Requirements

> 역할: `MeshPaintPrepTool` v1.0의 필수 요구사항, 비범위, 완료 기준을 정의한다.
> 문서 버전: v0.2
> 마지막 정리(Asia/Seoul): 2026-06-29
> 상태: Draft / Requirements

---

## 1. 목표

v1.0 목표는 아래 한 문장으로 고정한다.

```text
사용자가 Static Mesh 하나를 선택하고 버튼을 누르면,
해당 메시를 Texture Color Mesh Painting 가능한 상태로 준비한다.
```

사용자는 이후 Unreal Editor의 `메시 페인트(Mesh Paint)` 모드에서 직접 색칠한다.

---

## 2. 사용자 시나리오

### 2.1 터렛 메시

1. 사용자가 모델링 모드(`Modeling Mode`)에서 박스와 실린더로 터렛 형태를 만든다.
2. Static Mesh로 저장한다.
3. `MeshPaintPrepTool`을 실행한다.
4. UV가 없으면 Auto UV를 생성한다.
5. 페인트 텍스처와 머티리얼 인스턴스를 만든다.
6. 사용자가 메시 페인트(`Mesh Paint`)에서 텍스처에 색칠한다.

### 2.2 총알 메시

1. 사용자가 실린더 또는 캡슐형 메시를 만든다.
2. 툴에서 작은 해상도의 페인트 텍스처를 선택한다.
3. 단순 색상 또는 탄두 표시를 텍스처 페인트로 칠한다.

### 2.3 차량 차체

1. 사용자가 테스트 차량 메시를 선택한다.
2. 툴이 기존 UV와 페인트 머티리얼 상태를 검사한다.
3. 필요한 경우 빈 페인트 텍스처와 머티리얼 인스턴스를 새로 만든다.
4. 스폰 차량도 같은 메시와 머티리얼을 쓰도록 검증한다.

## 3. v1.0 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---:|
| R001 | 선택한 `Static Mesh`를 입력으로 받는다. | 필수 |
| R002 | Skeletal Mesh, Landscape 등 비대상 타입은 거부한다. | 필수 |
| R003 | UV 채널 존재 여부를 검사한다. | 필수 |
| R004 | UV가 없거나 사용자가 선택하면 Auto UV를 생성한다. | 필수 |
| R005 | 기본 페인트 UV 채널은 `UV0`으로 둔다. | 필수 |
| R006 | 빈 페인트 텍스처를 생성한다. | 필수 |
| R007 | 페인트용 머티리얼 인스턴스를 생성한다. | 필수 |
| R008 | 선택한 메시의 지정 슬롯에 머티리얼 인스턴스를 적용한다. | 필수 |
| R009 | 생성된 에셋을 저장한다. | 필수 |
| R010 | 이미 같은 이름의 에셋이 있으면 덮어쓰기 여부를 묻거나 새 이름을 제안한다. | 필수 |
| R011 | 실패 사유를 에디터 알림 또는 로그로 보여준다. | 필수 |
| R012 | CarFight 전용 에셋 경로를 하드코딩하지 않는다. | 필수 |

## 4. v1.0 UI 요구사항

툴 패널은 아래 입력을 제공한다.

| 항목 | 기본값 | 설명 |
|---|---|---|
| 대상 메시 | 현재 선택한 Static Mesh | 콘텐츠 브라우저 또는 레벨 선택에서 가져온다 |
| 대상 슬롯 | 0번 슬롯 | 여러 머티리얼 슬롯이 있으면 선택 가능해야 한다 |
| UV 처리 | UV 없으면 Auto UV | 기존 UV 사용 / Auto UV 생성 / UV 없으면 Auto UV |
| UV 채널 | UV0 | v1.0 기본값, 고급 옵션은 후속 |
| 텍스처 해상도 | 1024 | 256 / 512 / 1024 / 2048 후보, 작은 메시에는 낮은 해상도 권장 |
| 출력 폴더 | 메시 폴더 아래 `Paint` | 사용자가 변경 가능 |
| 에셋 접두어 | 자동 | `T_`, `MI_`, `M_` 규칙 사용 |
| 머티리얼 적용 | 켜짐 | 생성 후 메시 슬롯에 바로 적용 |
| 저장 | 켜짐 | 생성 / 수정 에셋 저장 |

## 5. 생성 에셋 요구사항

선택 메시 예시:

```text
/Game/Props/Turret/Mesh_Turret
```

기본 출력 예시:

```text
/Game/Props/Turret/Paint/T_Mesh_Turret_Paint
/Game/Props/Turret/Paint/MI_Mesh_Turret_Paint
```

플러그인 기본 부모 머티리얼 예시:

```text
/MeshPaintPrepTool/Materials/M_PaintableMesh
```

생성 규칙:

| 에셋 | 이름 규칙 | 역할 |
|---|---|---|
| Texture2D | `T_{MeshName}_Paint` | 사용자가 칠할 텍스처 |
| Material Instance | `MI_{MeshName}_Paint` | 메시 슬롯에 적용할 인스턴스 |
| Parent Material | `M_PaintableMesh` | 플러그인 기본 페인트 머티리얼 |

## 6. 비범위

v1.0에서 하지 않는다.

| 항목 | 이유 |
|---|---|
| Skeletal Mesh 페인트 준비 | Static Mesh부터 안정화 필요 |
| 런타임 페인트 저장 | Editor Utility 범위와 다름 |
| 데칼 생성 | 텍스처 페인트 준비와 용도가 다름 |
| 고품질 수동 UV 제작 | Auto UV는 시작점이고 아트 품질 보장은 아님 |
| 복잡한 UV1 / UV2 워크플로 | v1.0은 UV0 기준으로 단순화 |
| Marketplace 배포 자동화 | 별도 레포 안정화 이후 결정 |
| 프로젝트별 DataAsset 연결 | 플러그인 범위가 아니라 각 게임 프로젝트 책임 |

---

## 7. 완료 기준

v1.0 완료 기준:

1. 플러그인이 Editor-only로 로드된다.
2. Static Mesh 하나를 선택해 툴을 실행할 수 있다.
3. UV가 없는 단순 메시에서 Auto UV 생성 후 페인트가 보인다.
4. 빈 텍스처와 머티리얼 인스턴스가 생성된다.
5. 메시 페인트(`Mesh Paint`)에서 그린 결과가 메시 페인트 모드 밖에서도 보인다.
6. 같은 메시를 스폰하거나 다른 레벨에 배치해도 동일 머티리얼이면 페인트가 보인다.
7. CarFight 전용 경로 없이 다른 프로젝트에서도 플러그인을 복사 또는 서브모듈로 사용할 수 있다.

## 8. 결정 상태

아래 항목은 구현 또는 레포 생성 전에 확인한 결정 상태다.

| ID | 항목 | 현재 상태 |
|---|---|---|
| Q001 | 별도 Git 원격 저장소 URL | 확정: `https://github.com/serenieal/MeshPaintPrepTool` |
| Q002 | 저장소 공개 범위 | 확정: 비공개 |
| Q003 | 라이선스 | 확정: 현재는 만들지 않음 |
| Q004 | 기본 텍스처 해상도 | 확정: 기본 1024, 256 / 512 / 2048 선택 가능 |
| Q005 | 플러그인 아이콘 / 메뉴 이름 한글 표시 여부 | 확정: 표시 이름은 `Mesh Paint Prep`, 사용자 안내 문구는 한글 |

## 9. Changelog

### v0.2

- 원격 저장소 URL, 비공개 저장소, 라이선스 없음 결정을 반영했다.
- 텍스처 해상도 정책을 기본 1024로 두되 작은 메시를 위해 256 / 512 선택을 허용하도록 갱신했다.
- 플러그인 UI 표시 이름을 `Mesh Paint Prep`으로 확정했다.

### v0.1

- v1.0 필수 요구사항을 Static Mesh 기준으로 정리했다.
- 차량, 터렛, 총알, 임시 프롭 시나리오를 포함했다.
- Auto UV와 UV0 기본 정책을 요구사항으로 포함했다.
- 별도 Git 저장소 관련 미결 항목을 `Open Question`으로 분리했다.

## 10. Migration 메모

- 기존 차량 테스트에서 만든 `M_CarPaintSkin`, `MI_TestSedanSkin`, `MI_TestSUVSkin`은 플러그인 요구사항의 참고 사례다.
- 새 플러그인은 `M_PaintableMesh` 계열을 사용한다.
- 기존 차량 전용 명명은 새 플러그인 생성 에셋 이름에 사용하지 않는다.
