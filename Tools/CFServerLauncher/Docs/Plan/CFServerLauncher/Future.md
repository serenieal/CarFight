# CFServerLauncher v1.1 이후 확장 후보

문서 버전: v1.0.1  
작성 기준일: 2026-05-29

## 1. 문서 목적

이 문서는 `CFServerLauncher` v1.0 완성 이후 검토할 수 있는 확장 후보를 정리한다.

`Roadmap.md`는 v1.0 완성까지의 로드맵으로 사용한다.  
이 문서는 v1.0 완료 전에는 구현 대상으로 보지 않는다.

## 2. 확장 원칙

v1.1 이후 기능은 다음 조건을 만족할 때만 추가한다.

1. v1.0 기능이 반복 테스트에서 안정적이다.
2. 기능 추가가 서버 코드와 런처 코드의 분리를 크게 해치지 않는다.
3. 1인 개발 유지보수 비용이 감당 가능하다.
4. 기능이 실제 운영 흐름을 단순하게 만든다.

## 3. v1.1 후보: 실행 프로필

여러 서버 실행 설정을 프로필로 관리한다.

예시:

```text
로컬 테스트 서버
내부 QA 서버
밸런스 테스트 서버
```

프로필별로 관리할 수 있는 값은 다음과 같다.

- 서버 EXE 경로
- 작업 폴더
- 맵 경로
- 포트
- 로그 파일 경로
- 추가 인자

주의점:

- v1.0 설정 JSON과 호환되도록 마이그레이션이 필요하다.
- UI가 복잡해질 수 있으므로 콤보박스 기반으로 단순하게 시작한다.

## 4. v1.1 후보: 날짜별 로그 파일

서버 실행마다 로그 파일명을 다르게 만든다.

예시:

```text
server_20260526_143500.log
```

장점:

1. 이전 실행 로그를 보존할 수 있다.
2. 크래시 원인 분석이 쉬워진다.
3. 테스트 기록을 남기기 좋다.

주의점:

- 로그 파일이 계속 쌓이므로 정리 정책이 필요하다.
- v1.0의 단일 `server.log` 정책보다 관리 복잡도가 높다.

## 5. v1.1 후보: 간단 모니터링

외부 프로세스 기준으로 다음 값을 표시한다.

- 실행 시간
- CPU 사용량
- 메모리 사용량
- 프로세스 응답 상태

주의점:

- v1.0에서는 실행 상태와 PID만 표시한다.
- 성능 모니터링은 OS 프로세스 기준으로만 처리한다.
- 서버 내부 TPS, 접속자 수, 게임 상태는 v1.1 대상이 아니다.

## 6. v1.2 후보: 자동 재시작

서버가 비정상 종료되었을 때 자동으로 다시 시작하는 기능이다.

필요 설정:

- 자동 재시작 사용 여부
- 재시작 최대 횟수
- 재시작 대기 시간
- 정상 종료와 비정상 종료 구분

주의점:

- 무한 재시작 위험이 있다.
- 서버 크래시 원인을 숨길 수 있다.
- v1.0에서는 넣지 않는다.

## 7. v1.2 후보: 로그 검색/필터

로그 UI에서 문자열 검색이나 레벨 필터를 제공한다.

후보 기능:

- 문자열 검색
- Error/Warning 필터
- 로그 파일 열기
- 로그 폴더 열기

주의점:

- 로그 파싱 규칙이 Unreal 로그 포맷에 묶일 수 있다.
- v1.0에서는 단순 tail 표시만 유지한다.

## 8. v1.3 후보: 빌드/Cook/Stage 연동

Unreal Build Tool 또는 RunUAT를 호출하는 기능이다.

후보 기능:

- 서버 빌드 실행
- Cook 실행
- Stage 실행
- BuildCookRun 프리셋 저장

주의점:

- 이 기능은 서버 런처보다 빌드 도구에 가깝다.
- 실행 시간이 길고 실패 케이스가 많다.
- 로그 분리와 오류 분석 UI가 필요하다.
- v1.0과 v1.1에서는 제외하는 것이 좋다.

## 9. v1.3 이후 후보: RCON 또는 관리자 명령

서버 내부 명령 채널을 통해 graceful shutdown이나 관리 명령을 보내는 기능이다.

후보 기능:

- 정상 종료 요청
- 맵 변경
- 현재 접속자 조회
- 킥/밴
- 서버 메시지 방송

주의점:

- Unreal C++ 서버 코드와 결합이 생긴다.
- 인증과 권한 처리가 필요하다.
- 서버 코드와 런처 코드의 강한 분리 원칙이 약해질 수 있다.
- 반드시 별도 설계 문서가 필요하다.

## 10. 장기 후보: 웹 대시보드

원격에서 서버 상태를 보는 웹 UI이다.

후보 구성:

```text
서버 관리 API
웹 UI
인증
권한 관리
원격 로그 조회
```

주의점:

- 보안 요구사항이 크게 증가한다.
- 외부 네트워크 노출 여부를 결정해야 한다.
- WPF 런처와 별도 프로젝트로 분리하는 것이 좋다.

## 11. 우선순위 추천

v1.0 이후 추천 순서는 다음과 같다.

```text
1. 실행 프로필
2. 날짜별 로그 파일
3. 간단 모니터링
4. 로그 검색/필터
5. 자동 재시작
6. 빌드/Cook/Stage 연동
7. RCON 또는 관리자 명령
8. 웹 대시보드
```

## 12. 보류해야 할 기능

다음 기능은 현재 단계에서 보류한다.

- 접속자 제어
- 게임 상태 조회
- 서버 내부 변수 변경
- 맵 내부 액터 제어
- uasset 수정
- 원격 관리자 권한 시스템

이 기능들은 단순 런처 범위를 넘어선다. 별도의 서버 관리 시스템 설계가 필요하다.
